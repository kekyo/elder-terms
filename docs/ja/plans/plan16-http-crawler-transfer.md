# plan16：HTTP/HTTPSによる簡易クローラ型ファイル受信

作成日：2026年11月2日

状態：計画作成。実装は未着手です。設定名と探索上限は初期案であり、段階1で実例を使って確定します。

## 目的と範囲

基準URLのHTMLに含まれるリンクから、ファイル転送画面に擬似的なディレクトリを表示します。対象は絶対URLと相対URLの両方です。基準URLの配下にあるリンクだけを残し、自己参照や循環リンクで探索が終わらなくなることを防ぎます。

探索は項目単位の遅延処理とします。接続時に取得するのは開始ページだけです。リンク先は未判定の項目として表示し、利用者が展開・移動した項目、または指定した受信に必要な項目だけを取得します。最初のURLから到達できる全リンクの先行クロールは行いません。

HTTPとHTTPSは同じ転送方式の設定で選びます。HTMLの取得、一覧の閲覧、ファイルとディレクトリの受信を対象とし、書き込み操作は利用不可とします。WebDAVは既存の独立した方式として維持します。JavaScriptの実行、ログイン画面の操作、Webページの表示内容を再現する機能は含めません。

調査基準、実施手順、TDD、コミット、全体テストの条件は[plan15](plan15-transfer-jobs-and-tree-icons.md)の共通条件に従います。

共通HTTP層へ分離するのは通信、応答、TLS、認証、キャンセルです。WebDAV固有のXMLやパス規則は残します。URLの相対解決は[libcurlのURL API](https://curl.se/libcurl/c/libcurl-url.html)または既存GLibの公開URI APIを比較し、採用版のコメントを確認して一方に統一します。

[libxml2のHTML解析API](https://gnome.pages.gitlab.gnome.org/libxml2/html/HTMLparser_8h.html)は、ブラウザーのHTML5処理と同等ではありません。通常のディレクトリ一覧や単純なHTMLのリンクを対象に検証し、DOMの再現精度を完了条件にしません。

## 基準URLと探索範囲

URLの同一性と配下判定を、表示名やローカルパスから分離します。ここでオリジンはスキーム、ホスト、実効ポートの組です。ホストの大文字・小文字と省略された既定ポートを正規化し、HTTPとHTTPSは異なるオリジンとして扱います。

基準URLは配下を定めるディレクトリURLを基本とします。たとえば`https://host/pub/`で許可するのは`/pub/a.zip`などです。`/public/a.zip`、`/other/`、別ホストは除外します。判定にはパス区切りを含む境界を使います。

`https://host/pub/index.html`を開始ページにしたい場合の推奨案は、基準URL`https://host/pub/`と開始ページURLを分ける設定です。開始ページは基準URL配下に限定し、省略時は基準URL自身を取得します。ファイル形式のURLから親ディレクトリへ許可範囲を自動で広げる仕様にはしません。段階1ではこの二項目の操作を確認し、基準URL一項目だけにする場合の制限も明記して決定します。

| 入力・応答 | 扱い |
| --- | --- |
| 絶対URL、`/pub/a`、`a`、`../a`、`//host/pub/a` | 現在のページの最終URLを基準に解決し、その後でオリジンと配下を再検査する |
| `<base href>` | 解決基準に反映するが、許可範囲は設定済みの基準URLのままにする |
| HTML実体参照 | HTML解析で復元してからURLとして扱う |
| `.`、`..`、パーセント表記 | 一貫した正規化で比較する。区切りや親移動の解釈が曖昧な入力は除外し、二重デコードしない |
| `#fragment` | リソースの同一性と通信先から除く。同じページ内のリンクは新しい子ノードにしない |
| `?query` | リソースの識別情報として保持する。順序の変更や無条件の削除は行わない |
| HTTPの3xx | `Location`を一段ずつ解決・検証する。範囲外には接続せず、循環と回数超過を終了理由として示す |
| `mailto:`、`javascript:`、`data:`など | HTTP/HTTPS以外は転送ツリーに含めない |

相対参照と正規化の根拠は[RFC 3986の5・6節](https://www.rfc-editor.org/rfc/rfc3986.html#section-5)です。URLの解析と送信で異なる解釈を使わないことを、通信先を記録する試験サーバーで検証します。

## リンク先のHTML判定

HTMLかどうかは、その項目を実際に取得した応答で判定します。URL末尾の`/`や`.html`は表示の手掛かりに留め、解析対象を確定する条件にはしません。拡張子がないHTMLや、末尾が`/`でもコンテンツを返すURLを扱うためです。

| 応答と操作 | 扱い |
| --- | --- |
| 展開時に`Content-Type: text/html` | 本文を上限付きで取得し、そのページ自身のリンクだけを解析する |
| 展開時に`Content-Type: application/xhtml+xml` | XHTMLとして解析する。採用するlibxml2の公開APIで名前空間を扱う |
| `Content-Disposition: attachment` | 保存用コンテンツを既定の扱いとし、自動のリンク探索へ回さない |
| HTML以外の明示された型 | コンテンツとして確定する。展開目的なら本文を最後まで取得せず、その項目に子がないことを反映する |
| 型の省略・不正・汎用バイナリー型 | 自動ではHTMLと断定せずコンテンツとして扱う。誤設定のサーバーには、対象一件を「HTMLとして展開」する操作を用意する案とする |
| 「ファイルとして受信」を指定 | HTMLを含め、応答そのものを保存する。本文中のリンクは探索しない |

判定ではメディア型と`charset`などのパラメーターを分け、最終的な成功応答のヘッダーを使います。エラー画面のHTMLを一覧として取り込まないよう、HTTPステータスも先に確認します。基準は[RFC 9110のContent-Type](https://www.rfc-editor.org/rfc/rfc9110.html#name-content-type)と[RFC 6266のContent-Disposition](https://www.rfc-editor.org/rfc/rfc6266.html#section-4.2)です。

HTMLの応答だけでは、一覧用ページと、保存したいHTML文書を完全には区別できません。そのため、HTMLの項目には「リンク一覧として展開」と「ファイルとして受信」の両方を提供します。通常の展開操作で擬似ディレクトリを閲覧でき、同じURLの原文も保存できる構成です。

## 項目単位の探索と循環の扱い

`a href`から得たURLは、取得先を正規化した未判定の項目として並べます。未判定は通常ファイルの`other`と区別し、展開を試せることを表示します。この状態を分類情報として持ち、行の描画、アイコン決定、ソートのためにリンク先を取得しません。

| 操作 | 新たに取得する範囲 |
| --- | --- |
| 接続・開始ページの表示 | 開始ページと、その取得に必要な許可範囲内のリダイレクトだけ |
| 一つの項目を展開・そのURLへ移動 | 対象URLの応答だけ。HTMLなら得られた子を未判定として追加する |
| 行の選択、ポインターの移動、アイコンの表示 | 取得しない |
| 展開済みの項目を閉じて再展開 | 保持中の一覧を使う。更新を指示されたときに対象ページだけ再取得する |
| 一つのファイルを受信 | 対象URLだけをストリーミング受信する |
| 「ディレクトリとして受信」を指定 | 選択した入口の配下だけを、必要になった項目から順に探索・受信する。別の枝を調べたり、総サイズを知るためにサイト全体を先行走査したりしない |

通常の取得はGETを使い、全子要素へHEADを配る処理は追加しません。展開目的で非HTMLと判明した場合は、その分類結果を保持して本文の取得を打ち切ります。これを通信障害や受信成功と混同しないよう、HTTP層の終了理由を区別します。ファイル受信として開始したGETは、そのまま本文を保存できます。

深いパスへのリンクに中間の擬似ノードが必要な場合も、親ページで判明した情報だけから作ります。存在確認のために中間URLを先読みしません。実在する一覧ページと、既知の子だけをまとめた擬似ノードを区別します。

探索中の祖先URL、取得済みページの集合、転送済みリソースの集合を分けます。祖先へ戻る辺はツリーから除き、一つの再帰受信で同じページを再取得しません。別の枝や利用者の再訪まで永久に禁止しないよう、訪問済み集合は探索・ジョブ単位で管理します。リダイレクト元と最終URLは同じリソースの別名として関連付けます。

初期上限の候補は、HTML本文2MiB、リダイレクト5回、深さ32、ページ数1,000、リンク数10,000です。本文の上限は一ページ、深さ・ページ数・リンク数は一つの探索操作または再帰受信ジョブに適用します。上限を設けるための先行クロールは不要です。クエリーだけが無限に変わるリンクでも終了し、上限に達した結果を「完全な受信成功」と表示しない契約にします。

表示名と保存先はURLのパス成分から作ります。リンクの表示テキストや`Content-Disposition`を、そのままパスとして使用しません。クエリー違いの同名リソース、パーセント表記、空名、日本語名の衝突を区別し、ローカルの選択ディレクトリ内へ保存します。決定した名前はジョブ内で固定します。

## 設定と転送画面

設定候補は基準URL、開始ページ、ユーザー名、初期ローカルディレクトリ、接続・無通信の期限です。パスワード、TLSの判断、SSH proxyは既存の実行時入力と方針を再利用します。URL自身には認証情報を埋め込みません。

リモート側は一覧の更新、展開、パス移動、ファイルとしての受信、ディレクトリとしての受信を提供します。送信、新規フォルダー、名前変更、削除、属性変更はUIとクライアントの両方で拒否します。ディレクトリ受信も選択した部分を順に処理し、未探索部分の件数や総量は未確定として表示する方針です。

`Content-Length`がない応答でもストリーミング受信を行い、plan15のジョブへサイズ不明として報告します。切断、キャンセル、HTML解析失敗、HTTPエラーを区別し、未完了ファイルの後始末は共通転送エンジンの契約を使います。

## 段階1：実際のHTMLから範囲内の一覧を作る

Node.jsのローカルHTTPサーバーと、一ページを取得して候補ノードを出力するネイティブドライバーを用意します。絶対・相対URL、範囲の境界、開始ページ、`base`、フラグメント、クエリー、文字参照、循環のケースをREDにしてから実装します。応答の型、拡張子なしのHTML、HTML名のバイナリー、添付指定、型の欠落も検証します。

この段階で基準URLの設定方法、分類、探索上限を確定します。完了条件は、範囲外へアクセスせず、開始ページの表示だけでは子URLへのGETもHEADも発生しないことです。子の一件を指定したときだけ、その応答を分類して一覧を取得できるところまで確認します。

## 段階2：読み取り専用クライアントでファイルを受信する

HTTPセッションの必要部分を共通化し、既存WebDAVの動作を確認しながらHTTPクライアントを実装します。ヘッダー受信後の分類と本文取得の制御、未判定項目の解決を実装し、ドライバーで一覧取得、単一・再帰受信、サイズ不明の進捗、キャンセル、再接続まで実行します。既存の一括事前探索を前提にせず、HTTPの再帰受信を逐次実行できるよう共通エンジンの契約も確認します。

リダイレクト後の別名判定、認証失敗、403・404・5xx、HEAD非対応、途中切断、同名ファイルの扱いを検証します。HEADが使えなくてもGETによる受信が成立することが条件です。完了条件は、受信内容の比較と失敗時の後始末が通り、既存WebDAVが動くことです。

## 段階3：設定・ツリー・ジョブへ統合する

接続種別と設定を追加し、保存・継承・入力検証・再接続へ接続します。ツリーの展開と複数選択による受信をplan15のアイコンとジョブで表示します。設定画面だけを先行させず、保存した接続で実際に受信できる単位でコミットします。

完了条件は、画面からHTTPとHTTPSに接続し、選んだ項目だけを展開・受信できることです。HTMLの原文保存、循環のある部分ツリーの再帰受信、読み取り専用の操作制限も確認します。

## 段階4：実通信・表示・全体検証

Node.jsの試験サーバーに加え、一般的な静的HTTPサーバーのディレクトリ一覧でも確認します。開始ページが多数のリンクを含む試験では、接続・行選択・展開・再展開・更新・部分ツリー受信ごとの要求先と要求数を記録します。未操作の枝へ通信しないこと、巨大な非HTMLを展開時に読み切らないことをアサートします。HTTPS、既存方式の証明書確認、SSH proxy、探索中の画面閉鎖、進捗表示も検証対象です。表示を目視確認し、進捗と中止は動画でも確認します。

利用者向け文書に基準URL、開始ページ、読み取り専用、上限時の表示を記載します。`make test`の成功と次の条件を照合して完了とします。

## 最終完了条件

1. HTTP/HTTPSの設定を保存し、開始ページから未判定の子を表示できる。未操作のリンク先を先行取得しない。
2. 絶対・相対URLを同じ規則で判定し、リダイレクトや`base`でも許可範囲を広げない。
3. 自己参照、祖先参照、重複、循環、無限のURL生成で探索が継続し続けない。
4. 操作した項目の応答からHTMLを判定し、ページの展開と原文の受信を選べる。再帰受信は指定範囲に限定し、サイズ不明、同名、切断、中止をジョブへ正しく反映する。
5. 書き込み操作を拒否し、WebDAVを含む既存転送の全体テストが通る。
