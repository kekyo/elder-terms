# HTTP/HTTPSからファイルを受信する

HTTP/HTTPS接続では、HTMLページのリンクをファイル転送画面に表示します。公開ディレクトリや単純なリンク集から、必要なファイルを選んで受信できます。リモート側は読み取り専用です。

## 接続先を設定する

接続種別で「HTTP/HTTPS」を選び、同名のタブに基準URLを入力します。基準URLはアクセスできる範囲を定めるディレクトリURLです。末尾に`/`を付け、ユーザー名・パスワード、クエリー、フラグメントを含めないでください。

たとえば、基準URLが`https://example.com/pub/`なら、`/pub/file.zip`は対象です。`/public/file.zip`や`/other/`、別のホスト・ポート・通信方式へのリンクは対象になりません。リダイレクト先にも同じ制限を適用します。

開始ページを別に指定する場合は「開始ページURL」を入力してください。基準URLからの相対URLも指定でき、空欄なら基準URLを使います。`index.html`から始めたい場合は、基準URLを`https://example.com/pub/`、開始ページURLを`index.html`とします。開始ページも基準URLの範囲内で指定してください。

## リンクを展開する

接続時には開始ページだけを取得します。リンク先は未判定の項目として表示されます。行の選択やアイコンの表示では通信しません。

項目を展開すると、そのURLの応答を取得して種類を判定します。HTMLならリンクを子として表示し、それ以外ならファイルとして表示します。拡張子や末尾の`/`だけで種類を決めることはありません。未判定の子は、利用者が操作するまで取得しません。

展開済みの一覧は接続中に保持します。閉じて開き直す操作では再取得せず、「更新」で現在のページだけを再取得します。

パス欄には、通信方式・ホスト名・ポートを除いたパスを表示します。例えば`https://example.com/pub/docs/`は`/pub/docs/`と表示されます。パスを入力してEnterを押すと、その場所へ移動できます。クエリーや末尾の`/`は別のページを表すことがあるため、表示に残します。`%3F`など予約文字のパーセント表記も維持します。

完全なURLの入力も受け付けます。パス欄からの移動や「上へ」の移動先は、設定した基準URLの範囲内に限ります。別のホスト・ポート・通信方式には切り替わりません。

通常は`text/html`と`application/xhtml+xml`の応答を展開します。添付ファイル指定の応答や、種類が不明な応答は保存用のファイルとして扱います。サーバーがHTMLの種類を正しく通知しない場合は、対象を右クリックして「HTMLとして展開」を選んでください。

## ファイルとディレクトリを受信する

Localで保存先のフォルダーを1つ選んでから、Remoteで受信する項目を選び、右クリックメニューで受信方法を選びます。受信する項目は複数選べます。保存先が未選択の場合や、フォルダー以外または複数の項目を選んだ場合は、どちらの受信方法も選べません。Localのパス欄の場所は保存先として使いません。

| 操作 | 受信する内容 |
| --- | --- |
| ファイルとして受信 | 選択したURLの応答をそのまま保存します。HTMLも原文を保存し、リンク先は取得しません。 |
| ディレクトリとして受信 | HTMLのリンクを順に調べ、配下をローカルのフォルダーへ保存します。HTML以外の応答はファイルとして保存します。 |

ディレクトリ受信では、選択した項目から必要になったリンク先を順に取得します。総サイズを調べるための先行探索は行いません。同じ受信ジョブで既に処理したURLや、祖先に戻るリンクを繰り返し辿ることもありません。

保存名はURLのパスから決めます。日本語として復号できない名前はパーセント表記を保ち、クエリー違いなどで名前が重なる場合は連番で区別します。表示名から取得先URLを作り直すことはありません。既存ファイルとの競合は共通の上書き確認で扱います。

探索中の件数や総サイズは未確定です。サイズを通知しないファイルも受信でき、ジョブ一覧には受信済みの量を表示します。中止や途中切断では未完成のファイルを取り除きます。一時ファイルの回収に失敗した場合は、ジョブの詳細を確認してください。

送信、新規フォルダー、名前変更、削除、属性の変更は使用できません。

## 探索の上限と対応範囲

| 対象 | 上限 |
| --- | --- |
| 1ページのHTML本文 | 2MiB |
| 1回の取得のリダイレクト | 5回 |
| 再帰受信の深さ | 32 |
| 再帰受信のHTMLページ数 | 1,000 |
| 1ページまたは再帰受信で処理するリンク数 | 10,000 |

上限に達した場合は理由を表示し、完全な受信成功として扱いません。対象を絞って受信してください。既に受信が完了したファイルは保持します。

HTMLの文字コードはBOM、HTTPのcharset、meta宣言の順で選び、宣言がなければUTF-8として扱います。宣言された文字コードで復号できない本文はエラーです。URLのパーセント表記は本文の文字コードとは別に保持します。

転送内容を正しく保存するため、非圧縮のHTTP応答を要求します。この指定を無視して圧縮応答を返すサーバーでは受信が失敗します。

HTMLの`a href`によるリンクを対象にします。JavaScriptの実行、ログインフォームの操作、画像やスタイルを集めてWebページを再現する機能はありません。HTML解析に使う[libxml2のHTMLパーサー](https://gnome.pages.gitlab.gnome.org/libxml2/html/HTMLparser_8h.html)は、ブラウザーと同じHTML5処理を保証しません。

## 認証・証明書・SSH proxy

認証なし、Basic、Digest、自動選択を指定できます。認証を使う場合は接続時にユーザー名とパスワードを入力します。パスワードは保存しません。自動選択の対象はBasicとDigestです。

HTTPSはTLS 1.2以上を使用し、証明書と接続先名を検証します。独自CAはPEMファイルで指定してください。検証に失敗したときは既定で接続を拒否します。「オーバーレイで確認」を選ぶと、その接続に限って表示された証明書を許可できます。例外は保存されません。確認方式の詳細とTLSバックエンドの制約は[WebDAVの証明書確認](webdav.md#HTTPSの証明書確認)と共通です。

[SSH proxy](ssh-proxy.md)による踏み台経由の接続にも対応します。最終接続先の名前解決は踏み台で行い、HTTPSの証明書は元の接続先名で検証します。

## 設定ファイル

各項目は接続の既定値を継承でき、接続ごとに上書きできます。

| `[http]`のキー | 既定値 | 意味 |
| --- | --- | --- |
| `base_url` | 空 | 必須の基準URL。HTTPまたはHTTPSのディレクトリURL。 |
| `start_url` | 空 | 基準URL内の開始ページ。空なら基準URL。 |
| `authentication` | `none` | `none`、`basic`、`digest`、`auto`。 |
| `username` | 空 | 接続時に入力するユーザー名の初期値。 |
| `local_directory` | 空 | 最初に表示するローカルディレクトリ。空なら共通の初期値。 |
| `ca_file` | 空 | PEM形式のCAファイルの絶対パス。空ならシステムのCA。 |
| `certificate_error_action` | `reject` | `reject`は接続拒否、`prompt`はオーバーレイで確認。 |
| `connect_timeout_seconds` | `30` | 接続の期限。1〜86400秒。 |
| `idle_timeout_seconds` | `60` | 通信が進まない場合の期限。1〜86400秒。 |

```ini
[general]
type=http
name=Published files

[http]
base_url=https://example.com/pub/
start_url=index.html
authentication=none
local_directory=/home/user/Downloads
```
