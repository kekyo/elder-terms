# plan22：文字背景色の透過・不透明モード

作成日：2026年11月2日

状態：計画作成。実装は未着手です。現在のboxrig公開APIではセルごとの背景不透明度を指定できないため、依存APIの検証を先行します。

## 目的

端末の文字背景色について、現在と同じ透過可能モードと、不透明モードを選べるようにします。既定値は透過可能です。たとえばエスケープシーケンスで緑の背景色を指定した場合、不透明モードではその緑を透けさせずに表示します。

端末の通常の背景、背景画像、デスクトップ透過、ぼかしの設定は別の役割を持ちます。本planの対象は、端末が文字セルへ指定した背景色です。共通の実施条件は[plan15](plan15-transfer-jobs-and-tree-icons.md)に従います。

## 現在のコードとAPIの制約

[terminal-background.cpp](../../../elder-terms-terminal/src/terminal-background.cpp)は、背景モードと背景画像の有無から透過要求を作り、`boxrig_ui_transparency_config.background_opacity`へ一つの値を渡しています。[terminal-background-editor.cpp](../../../shared/src/settings-widget/terminal-background-editor.cpp)には、その設定を編集する画面があります。

[terminal-color-filter.cpp](../../../shared/src/terminal-color-filter.cpp)は背景色の出自を見分け、既定色やパレット色に補正をかけています。しかし、現在の色補正APIから背景のalphaを変更することはできません。[boxrigの公開コメント](https://github.com/kekyo/boxrig/blob/46483d91f47f392ca580493326074e36b37df3d0/include/boxrig/ui/color.h)でも、`background_opacity`は入力値で、フィルターから変更できないとされています。[透過設定の公開型](https://github.com/kekyo/boxrig/blob/46483d91f47f392ca580493326074e36b37df3d0/include/boxrig/ui/view.h)は全体の背景alphaを一つ保持する構成です。

根拠となる同梱文書は[色補正](../../../deps/boxrig/docs/ja/color-filters.md)、[色API](../../../deps/boxrig/include/boxrig/ui/color.h)、[表示先API](../../../deps/boxrig/include/boxrig/ui/view.h)です。調査したboxrigのコミットは`46483d91f47f392ca580493326074e36b37df3d0`です。

## 表示する背景の規則

設定名の初期案は「文字背景の透過」、値は`transparent`と`opaque`です。通常の端末背景の不透明度と同じ設定行にはせず、背景設定の近くに独立した項目として置きます。設定はグローバル値の継承、接続ごとの上書き、実行中の適用に対応させます。

背景の判定に使うのは、色がどの指定から来たかという出自です。明示色が通常の背景と同じRGB値でも、不透明モードでは区別する必要があります。

| セルの背景 | 透過可能・既定 | 不透明 |
| --- | --- | --- |
| 端末の既定背景、SGR 49やリセット後 | 現在の背景不透明度に従う | 現在の背景不透明度に従う |
| SGR 40～47・100～107の背景色 | 現在の背景不透明度に従う | alpha 255で描画する |
| 256色・true colorによる背景色 | 現在の背景不透明度に従う | alpha 255で描画する |
| 明示色が既定背景と同じRGB | 現在の背景不透明度に従う | 指定の出自を保持してalpha 255にする |
| 明示背景を持つ空白・消去後のセル | 現在の背景不透明度に従う | 文字の有無にかかわらず背景を不透明にする |
| 選択、カーソル、IMEなどのマーカー | 既存の専用不透明度を使う | 同じ専用不透明度を使う |

SGRの反転表示は、反転後に背景となる色の出自で判断する案を採用候補とします。前景由来の色が背景へ移った場合は不透明、既定背景が背景として使われる場合は全体設定に従う規則です。色補正や背景反転フィルターによるRGB変換だけでは、この出自を変更しません。段階1で現在の反転処理との対応を確定します。

OSCで既定背景色を変更した場合も、既定背景である性質を保ちます。スクロールバック、alternate screen、画面の消去、端末の再アタッチで同じ規則を適用します。セルの論理属性を表示のために書き換えず、モードを戻すと現在の透過状態へ戻れる構成です。

## 必要な公開契約

アプリ側には、セル背景の出自に応じてalphaを選べる描画方針が必要です。公開設定で「全セルを既存の背景alphaで描く」と「既定背景以外のセル背景を不透明にする」を指定する形を候補にします。これは必要条件の案であり、現在存在するAPI名として扱いません。

背景画像やぼかしと合成する前にセルのalphaを確定し、GTK3で利用する描画バックエンドに同じ意味で適用できることが必要です。色フィルターはこれまでどおりRGBの補正を担当し、その結果の色を選択したalphaで合成します。

段階1では同梱API全体を再確認し、別の公開経路で正しく実現できるかも調べます。現在の調査結果どおり不足する場合は、必要なAPI、最小再現ドライバー、受け入れ条件を本planへ追記します。外部コードやサブモジュール参照は変更せず、別途提供・取り込みされた公開APIを利用できることを、アプリ側の実装開始条件とします。

ウインドウ全体を不透明にしたり、文字の上から矩形を重ねたりする処理は、既定背景の透過や選択表示の要求を満たしません。要求を満たす公開APIがない状態で、設定項目だけを追加して完了にはしません。

## 段階1：描画を再現し、依存APIを検証する

既存の[terminal-background-state-test.cpp](../../../elder-terms-terminal/tests/cpp/terminal-background-state-test.cpp)と[terminal-background.test.ts](../../../elder-terms-terminal/tests/terminal-background.test.ts)を調査し、色の異なる下地の上へ同じ緑背景を描く再現テストを追加します。透過可能モードでは下地で見え方が変わり、不透明モードでは同じ緑になることを要求としてRED確認します。

SGR 49、通常色と同じRGBの明示色、空白、反転もドライバーから出力します。成果物は再現結果と公開APIの適合表です。完了条件は、前節の描画契約を満たすAPIが利用可能であることです。不足する場合は依存待ちを記録し、段階2以降の実装を完了扱いにしません。

## 段階2：設定と単純な描画を完成させる

依存条件を満たした後、設定定義・保存・継承と背景エディターへ項目を追加し、表示設定へ伝えます。既定の透過可能モードを保ち、実行中に切り替えられるようにします。

まず通常背景と16色の明示背景で、設定画面から結果を観測できる状態にします。完了条件は、緑の明示背景だけを不透明にし、SGR 49で通常の透過背景へ戻せることです。

## 段階3：すべての描画条件へ適用する

256色、true color、反転、空白と消去、OSCの既定背景変更、色補正、色覚補正、背景反転、背景画像を検証します。alpha 0、途中の値、255、表示倍率、スクロール、履歴、alternate screen、再アタッチも含めます。

選択・カーソル・IMEがそれぞれの不透明度を保ち、明示背景の上でも正しく見えることを確認します。完了条件は、表示の出自と合成順序が前述の表に一致し、切替前のセルにも新しい設定が反映されることです。

## 段階4：実環境と全体検証

X11とWaylandの利用可能な透過環境、透過を使えない環境で確認します。後者では元から不透明に描画される場合があるため、その結果を設定の不適用と混同しません。

期待画像は目視で確認します。下地の変化による画素の差と、明示背景が維持する色をアサートし、画像ファイルの存在だけで合格にしません。全体の`make test`と利用者向け説明を完了させます。

## 最終完了条件

1. 透過可能・不透明を選べ、既定値と未設定時の動作は現在の透過可能のままである。
2. 明示した緑などのセル背景を不透明にし、既定背景は従来の透過設定に従う。
3. 同じRGB、反転、空白、色補正、背景画像、選択、カーソルでも出自と合成規則が一貫する。
4. 実行中の切替、履歴、再接続、再アタッチへ反映される。
5. 必要な公開APIを使用でき、外部コードを変更せず、目視確認と全体テストが完了している。
