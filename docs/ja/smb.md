# SMBの使用

SMBは、WindowsやSambaが公開する共有フォルダーに接続する方式です。elder-termsはSMB1・SMB2・SMB3で接続できます。既定はSMB2/3の自動選択です。SMB2/3では、experimental機能としてSSH proxyも利用できます。GVfsは使用しません。サーバー側で共有と利用者のアクセス権を用意してください。

## 接続する

ランチャーで接続を作成し、接続種別を「SMB」にします。SMBタブにサーバーのアドレスを入力して保存してください。接続後、リモート側の`/`にはサーバーが公開するファイル共有の一覧を表示します。共有名はサーバー上の共有フォルダーにつけられた名前です。

接続には、ユーザー名とパスワードを使うNTLM認証を使用します。ウィンドウを開くと、ユーザー名とパスワードを順に尋ねます。ユーザー名の初期値は設定した名前です。設定が空なら現在のOSユーザー名を表示します。ドメインを指定した場合は、その値を認証に使います。パスワードは接続のたびに入力し、設定ファイルへ保存しません。

共有を開くと、その中のファイルやフォルダーを閲覧できます。ツリーの展開、パスの入力、親への移動も利用できます。共有のルートで「Up」を選ぶと共有一覧へ戻ります。

| リモートパス | 表示する場所 |
| --- | --- |
| `/` | サーバーのファイル共有一覧 |
| `/team` | team共有のルート |
| `/team/Documents` | team共有内のDocumentsフォルダー |

共有名を独立して指定する設定はありません。最初から特定の共有を開く場合は、リモートディレクトリへ`/共有名/…`を指定します。`\\server\share`の形式は使用しません。従来の共有名設定を使っていた接続も、リモートディレクトリの先頭に共有名を含めるよう設定し直してください。旧設定の自動移行は行いません。

左右にローカルとリモートのフォルダーを並べて表示します。項目を選んで右クリックすると、ファイルやフォルダーの送受信、名前変更、削除、新しいフォルダーの作成ができます。フォルダーの送受信と削除は、その中の項目も対象です。同名の転送先があるときは、上書きするか、飛ばすかを選べます。

送信する前にRemoteで、受信する前にLocalで、フォルダーか通常のファイルを1つ選んでください。フォルダーを選ぶとその配下へ、ファイルを選ぶとそのファイルがあるフォルダーへ転送します。未選択の場合や、シンボリックリンクまたは複数の項目を選んだ場合は、送受信を選べません。パス欄の場所は転送先として使いません。

共有一覧の`/`への送信やフォルダー作成、共有自体の名前変更・削除はできません。一覧で共有を選ぶと、その共有内へ送信できます。共有を受信する操作と、共有内でのファイル・フォルダーの操作も利用できます。

「Close window when session ends」を無効にすると、通信が切れた後もウィンドウが残り、「再接続」から接続をやり直せます。通信中の操作を取り消した後も、再接続が必要になることがあります。接続が切れた操作を自動で繰り返すことはありません。再接続後に一覧を更新し、サーバー側の結果を確かめてから操作してください。

## SMBのバージョンを選ぶ

SMBタブのバージョンで、自動・SMB1・SMB2・SMB3を選べます。「自動・SMB 2/3」はSMB1を含みません。認証や接続に失敗しても、別のバージョンへ切り替えて再試行しません。実際に接続したバージョンは、ウィンドウのタイトルと転送ジョブに表示します。

SMB1はIPv4の直接接続に対応します。ポートは445、またはNetBIOS名を指定した139を使ってください。NetBIOS名はサーバーが使用する名前で、1～15文字の英数字・ハイフン・アンダースコアを指定します。IPv6、任意のポート、SSH proxy、署名・暗号化の要求には対応しません。これらは[libdsmの公開接続API](https://github.com/videolabs/libdsm/blob/0f3edc6df6ab5950f2550d453035351440f71e31/include/bdsm/smb_session.h)の制約です。対応しない組合せは設定欄にエラーを表示します。

SMB1では署名の組み込み既定値が無効になります。ただし、接続や継承元で署名を明示的に要求している場合は、その要求を残してエラーにします。SMB2で暗号化を要求した場合もエラーになります。

SMB1のファイル名はUnicodeで扱い、日本語や絵文字を使用できます。実行環境にはC.UTF-8ロケールが必要です。CP932などのコードページを選ぶ設定はありません。旧来のOEM文字列だけを扱うサーバーは対象外です。同梱libdsmには、[文字変換](https://github.com/videolabs/libdsm/blob/0f3edc6df6ab5950f2550d453035351440f71e31/src/smb_utils.c)をUTF-16へ修正するパッチを適用しています。変換不能な名前があれば一覧をエラーとし、その項目を欠いた一覧を成功として表示しません。

## IPスキャンで接続先を探す

SMBタブのアドレス欄の右側にある「IPスキャン」から、接続先を探索できます。「SMB(445)」のチェックマークはTCP接続を受け付けた候補です。SMBへの対応、認証や共有へのアクセス権は、実際に接続して確認してください。

行をダブルクリックすると、取得済みのホスト名、または数値IPアドレスをアドレス欄へ入力します。ポート、ドメイン、ユーザー名、リモートディレクトリ、署名・暗号化設定などは維持されます。接続条件を確認して保存してください。接続中の読み取り専用設定ではスキャンボタンを使えません。

ほかの接続方式も含めた探索範囲や名前取得の動作は、[IPスキャンで接続先を探す](../../README_ja.md#IPスキャンで接続先を探す)を参照してください。

## 共有を一覧・閲覧できない場合

共有名が一覧にあっても、利用者にその共有を開く権限があるとは限りません。アクセスを拒否された場合は、その共有のエラーを表示し、ほかの共有は引き続き操作できます。

サーバーが共有一覧の取得を拒否しても、既知の共有にはアクセスできる場合があります。リモートパスへ`/team/Documents`などを直接入力するか、接続設定のリモートディレクトリに指定してください。一覧の取得成功は個別共有を開くための条件ではありません。

一覧が途中までしか取得できなかった場合はエラーを表示します。同梱libsmb2の列挙APIには続きの取得位置を指定する方法がないため、途中の結果を完全な一覧として表示しません。この場合も、既知の共有をパスで指定できます。[libsmb2の列挙API](https://github.com/sahlberg/libsmb2/blob/727feaaa6d0f4fed1bae57745fbc2c5db9a30e64/include/smb2/libsmb2-share-enum.h)と[列挙実装](https://github.com/sahlberg/libsmb2/blob/727feaaa6d0f4fed1bae57745fbc2c5db9a30e64/lib/smb2-share-enum.c)を参照してください。

SMB1も途中の共有一覧をエラーとして扱います。多数の共有があるサーバーなどで発生した場合は、既知の共有をパスで指定してください。[libdsmの共有列挙処理](https://github.com/videolabs/libdsm/blob/0f3edc6df6ab5950f2550d453035351440f71e31/src/smb_share.c)にも、部分一覧を破棄する修正を適用しています。

## 設定項目

接続の設定は`[smb]`に保存します。接続ごとの値は「接続の既定値」から継承できます。

| 項目・INIキー | 既定値 | 指定方法 |
| --- | --- | --- |
| バージョン `version` | `auto` | `auto`はSMB2/3、`1`・`2`・`3`は各バージョンを指定。 |
| アドレス `address` | 空 | ホスト名、IPv4、IPv6。SMB1はIPv4のみ。接続時に必須。 |
| ポート `port` | `445` | SMB2/3は1～65535。SMB1は445または139。 |
| NetBIOS名 `netbios_name` | 空 | SMB1の139番ポートで必須。サーバーのNetBIOS名を指定。 |
| ドメイン `domain` | 空 | NTLM認証のドメイン。空ならドメインを指定しない。 |
| ユーザー名 `username` | 空 | 認証画面に表示する初期値。 |
| ローカルディレクトリ `local_directory` | 空 | 左側の初期ディレクトリ。空なら共通の転送先設定を使用。 |
| リモートディレクトリ `remote_directory` | `/` | 共有一覧は`/`。個別共有は`/共有名/…`で指定。 |
| 署名を必須にする `require_signing` | SMB1は`false`、ほかは`true` | SMBメッセージの署名を必須にする。 |
| 暗号化を必須にする `require_encryption` | `false` | `true`なら暗号化できない接続を拒否する。`false`でもサーバーが暗号化を要求する接続は使用できる。 |
| 接続タイムアウト `connect_timeout_seconds` | `30` | SMB接続を待つ秒数。SSH踏み台への接続・認証には適用しない。1～86400。 |
| 無通信タイムアウト `idle_timeout_seconds` | `60` | 通信が進まない状態を待つ秒数。1～86400。 |

次の例では、team共有内のDocumentsフォルダーを最初に開きます。パスワードは記録しません。

```ini
[general]
type=smb
name=Team files

[smb]
address=files.example.com
domain=OFFICE
username=alice
remote_directory=/team/Documents
require_signing=true
require_encryption=false
```

## SSH proxy経由の接続（experimental）

SMB2/3で利用できます。接続の「SSH proxy」タブで踏み台を有効にすると、踏み台からSMBタブで指定したサーバーとポートへTCP接続します。踏み台とSMB共有には別々に認証します。踏み台から共有サーバーへ到達でき、TCP転送が許可されている必要があります。設定方法は[SSH proxyの使用](ssh-proxy.md)を参照してください。

共有一覧の取得と複数共有の閲覧・転送もSSH proxy経由で利用できます。共有を移動しても、踏み台の認証を繰り返す必要はありません。

SSHによる暗号化は手元から踏み台までです。踏み台から共有サーバーまでの通信については、SMBタブの署名と暗号化の設定が適用されます。
SMBの接続タイムアウトは、踏み台への接続と認証を待つ間には適用されません。待機を中止する場合は、接続ウィンドウを閉じてください。

## ファイル操作の注意点

SMB2/3では更新日時を表示・設定でき、SMB1では表示だけが可能です。リモートのPOSIX権限、シンボリックリンクの作成、リモートハッシュ計算には対応しません。SMB2/3では共有内のリンクやWindowsのjunctionを追跡しません。SMB1の[属性API](https://github.com/videolabs/libdsm/blob/0f3edc6df6ab5950f2550d453035351440f71e31/include/bdsm/smb_stat.h)ではリンクを識別できないため、サーバーが返すファイルやフォルダーとして扱います。

SMB2/3の送信では共有内に一時ファイルを作り、完了後に最終名へ変更します。通常の名前変更では、既存の同名項目を置き換えません。通信が切れ、サーバーで一時ファイルが作られたか分からない場合は、そのパスをエラーに表示します。所有を確認できない一時ファイルは自動削除しません。再接続して表示されたパスを確認し、不要であれば利用者が削除してください。

SMB1では専用の一時ディレクトリに送信内容を保存します。[libdsmのファイルAPI](https://github.com/videolabs/libdsm/blob/0f3edc6df6ab5950f2550d453035351440f71e31/include/bdsm/smb_file.h)に排他的なファイル作成の指定がないためです。上書きでは、既存ファイルをそのディレクトリの`previous`へ退避し、新しいファイルを送信先へ移動します。置換は原子的ではなく、送信先が一時的に存在しない期間があります。中断後の復元結果が不明な場合は、退避した内容を残し、一時ディレクトリの場所をエラーに表示します。通信の中止は、サーバー側の変更を取り消す操作ではありません。

サーバーが読み取り専用にしている共有では、一覧と受信を利用できます。送信や変更を試みると、サーバーの拒否を表示します。

## 同梱ライブラリのソースとライセンス

debパッケージに同梱する[libsmb2](https://github.com/sahlberg/libsmb2)のソース一式は、`/usr/share/doc/elder-terms/licenses/libsmb2/libsmb2-source.tar.xz`にあります。同じディレクトリの`COPYING`に構成要素ごとのライセンスが、`LICENCE-LGPL-2.1.txt`にライブラリのライセンス全文があります。

SMB1用の[libdsm](https://github.com/videolabs/libdsm)についても、対応するソースを`/usr/share/doc/elder-terms/licenses/libdsm/libdsm-source.tar.xz`に同梱します。同じ場所にライセンスの`COPYING`と、適用した不具合修正の`libdsm-correctness.patch`があります。

同梱のlibdsmと本プロジェクトによる修正は、LGPL 2.1以降の条件で提供します。元の著作権表示を保持し、変更した各ファイルに変更内容と日付を記載しています。elder-terms本体のライセンスはMITです。[LGPL 2.1](https://opensource.org/license/lgpl-2-1)の第2条・第4条・第6条に従い、修正済みソースとビルド定義を同梱し、共有ライブラリを差し替えられる構成にしています。

ソースはライブラリごとのtar.xz形式です。展開にはtarとxzを使用します。Debian系では`xz-utils`を用意してください。

libdsmは同梱ソースだけで再ビルドできます。Cコンパイラー、Meson、Ninja、pkg-config、libtasn1の開発ファイルと`asn1Parser`を用意してください。Debian系では、libtasn1関連のパッケージ名は`libtasn1-6-dev`と`libtasn1-bin`です。

```sh
mkdir libdsm-rebuild
cd libdsm-rebuild
tar -xJf /usr/share/doc/elder-terms/licenses/libdsm/libdsm-source.tar.xz
meson setup build source --prefix="$PWD/sdk" --libdir=lib \
  -Ddefault_library=shared -Dbinaries=false
meson compile -C build dsm
meson install -C build --no-rebuild --tags=runtime,devel
```

再ビルドしたライブラリは`libdsm-rebuild/sdk/lib/libdsm.so.3`です。公開インターフェイスの互換性を保った修正版を利用できます。標準debパッケージでは、elder-termsを終了してから`/usr/lib/elder-terms/libdsm.so.3`を差し替えてください。自分の利用のための改変と、その改変をデバッグするためのリバースエンジニアリングを禁止する追加条件は設けていません。
