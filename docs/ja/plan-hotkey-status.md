# 外部コマンド名とホットキー認識状態

## 方針と完了条件

外部制御CLIの実行ファイル名を `etctl` に統一する。ビルド、インストール、パッケージ検証、ヘルプ、画面上の案内、READMEの設定例を合わせて変更する。

Aboutパネルのバージョン表示の下に、ホットキーの検出方式（確認中、X11、GlobalShortcuts Portal、利用不可）と `etctl` の受付可否を表示する。検出方式は個別のキー登録成功を意味しない。非同期の環境判定が完了したら表示を更新し、開いたままでも古い結果を残さない。英語と日本語に対応する。

完了条件は、新しい名前でCLI操作とパッケージ検証が成功し、実際の環境判定に対応したAbout表示を確認でき、既存機能の全体テストが成功すること。

## 手順

1. CLI実行・表示コマンド・パッケージ検証を新しい名前に変更したテストと、英語／日本語のAbout状態テストを追加し、ランチャー全体テストでREDを確認する。
2. 名前変更と状態通知・表示を実装する。ランチャー全体テスト、ネイティブ全体テスト、インストール確認を実行し、意味のある成果物としてコミットする。

## API確認

表示更新には既存のGTKラベルを使用する。[Gtk.Label.set_text](https://docs.gtk.org/gtk3/method.Label.set_text.html) と [Gtk.Label.set_selectable](https://docs.gtk.org/gtk3/method.Label.set_selectable.html) の公式ドキュメント、およびGTKの `gtklabel.c` のAPIコメントを確認する。

## 検証方法の調整

GUIテスト基盤は内部Xvfbの `GDK_BACKEND` 上書きを禁止している。そのため、テスト基盤はX11のまま維持し、テスト対象だけをラッパーから起動してWaylandセッションとして判定させる。Aboutを開いた状態でX11とPortal利用不可の結果を英語／日本語で確認する。

Portal利用不可の判定では、テスト環境のD-Busがインストール済みPortalサービスの起動を試みるため、10秒のテスト待機では判定が完了しなかった。[GDBusの既定の応答期限](https://docs.gtk.org/gio/method.DBusConnection.call.html)を含む処理の完了を待つよう、状態確認の上限を45秒、該当テストの上限を60秒にした。固定時間後に成功扱いするのではなく、期待する表示への変化を検証する。製品側の判定処理や応答期限は変更しない。

## 検証結果

- 新コマンドの未配置、旧名の案内、About状態表示の欠如によるREDを確認した。
- ネイティブ全体テストは128件成功、2件スキップ。スキップは明示的な有効化を必要とするvsftpdとApache WebDAVの検証。
- 一時ディレクトリへのMesonインストール後、`usr/local/bin/etctl --help` の起動と新しい名前のヘルプを確認した。
- 英語／日本語のX11・自動登録不可の表示をテストし、About画面も目視確認した。実機Waylandコンポジターでの検証は行っていない。
- 最終のランチャー全体テストは8ファイル、101件成功、1件スキップ。スキップは任意実行のDebian trixie i386パッケージ検証。新しい名前でのCLI操作、警告のコマンド表示、パッケージ検証、非同期のAbout表示更新が成功し、完了条件を満たした。
