# plan23：名前付きテーマによる設定継承と編集画面の統合

作成日：2026年11月2日

状態：計画作成。実装は未着手です。継承順と画面の移動先に加え、テーマの保存先を`theme.ini`とすることが確定しています。INI内の形式、参照管理、既存セッションへの反映時期は初期案であり、段階ごとの検証対象です。

## 目的と利用例

必要な設定だけをまとめて名前を付け、接続から参照できる「テーマ」を追加します。テーマにタイトルバーと背景の色を定義して「赤テーマ」と名付ければ、各接続でそれを選ぶだけで同じ配色を利用できます。ここでのテーマは、アプリの設定値を共有する単位です。OSやGTKのテーマを切り替える機能とは区別します。

継承順は「グローバル既定値 → 選択したテーマ → 接続ごとの設定値」です。テーマを選ばない接続は、現在の継承順を維持します。テーマ内でも接続内でも、明示された項目だけが前の層を上書きする構成です。

| 設定例 | グローバル既定値 | 赤テーマ | 接続A | 接続Aの表示 |
| --- | --- | --- | --- | --- |
| タイトルバー背景 | 灰色 | 赤色 | 未指定 | 赤色 |
| 本文背景 | 黒色 | 暗い赤色 | 青色を明示 | 青色 |
| 文字サイズ | 12 | 未指定 | 未指定 | 12 |

ランチャー下部のボタンから開く「接続の既定値」は、アプリケーション設定内へ移します。同じ画面に「テーマ」タブを追加し、テーマの作成、編集、参照の確認を行えるようにします。

調査基準は`def2ddc7`です。共通のTDD、段階ごとのコミット、全体テスト、文書更新の条件は[plan15](plan15-transfer-jobs-and-tree-icons.md)に従います。

## テーマに含める設定

テーマは名前、安定した参照用ID、明示した設定項目の集合を持ちます。IDは作成時に付け、名前の変更でも維持します。接続はIDを保存し、画面には名前を表示する方針です。複製時には別のIDを発行します。

対象は、現在グローバル既定値から接続へ継承できる登録済みの設定項目です。色だけに限定せず、文字サイズ、背景、入力や転送などの既存設定にも同じ規則を使います。値の型、範囲、正規化、設定間の整合性は既存の定義に従います。

アプリ全体だけに属する言語、起動方法、アプリのホットキーなどは、テーマに含めません。接続名、接続ID、接続アイコン、接続起動キーも、現在の継承対象外という扱いを維持します。テーマの選択値自体は接続専用とし、グローバル既定値や別のテーマから継承させません。

マクロやリンクの認識・起動ルールは、現在の`SettingEntry`による継承とは別のコレクションです。本planではこれらのコレクションに新しい継承規則を作りません。リンクの表示設定など、通常の設定項目として定義された値は対象です。

一つの接続で選べるテーマは一つです。テーマ同士の継承、複数テーマの重ね合わせ、配布サービスやインポート機能は今回の範囲に含めません。

## 値を解決する規則

実際の読み込みには組み込み値と起動時の上書きもあるため、順序を次のように定めます。

```text
組み込み値
  → global.iniのグローバル既定値
  → theme.iniから明示的に選択したテーマの定義済み項目
  → 接続INIの明示値
  → 起動時INIの明示値
  → 実行中に適用した明示値
```

テーマの選択は、接続・起動時設定に書かれた参照から先に解決します。起動時設定が参照を指定していなければ、接続の選択が有効です。起動時設定で明示的に「なし」を選んだ場合はテーマを外します。

テーマ選択を確定してから継承値を作り、各層の明示値を適用します。接続の読み込み後にテーマの値を上書きすると、優先順が逆転するためです。

| 状況 | 解決する値 |
| --- | --- |
| テーマを選んでいない | グローバル既定値と接続の明示値を現在どおり使用する |
| テーマで項目を定義していない | グローバル既定値、なければ組み込み値を使用する |
| テーマで定義し、接続では未指定 | テーマの値を使用し、継承元にテーマ名を表示する |
| 接続で項目を明示 | テーマより接続の値を優先する |
| 接続の明示値を解除 | 現在のテーマの値、なければグローバル既定値へ戻る |
| テーマの項目を解除 | その項目はテーマから消え、グローバル既定値を継承する |
| テーマを別のものへ変更、または「なし」にする | 継承値を作り直し、接続の明示値を保持する |

未指定と、空文字、`false`、0、色の`none`などの有効な明示値を区別します。また、下位層と同じ値でも、利用者が明示した指定は残します。たとえば接続で赤を明示した後にテーマを緑へ変えても、その接続の明示値は赤のままです。既存の`set_explicit_setting_value()`と明示解除の契約を基準に検証します。

テーマを適用した実効値を、そのまま接続の明示値として保存しません。接続にはテーマの参照と接続で指定した項目だけを保存し、テーマにはテーマで指定した項目だけを保存します。これにより、テーマの更新が次の読み込みにも反映されます。

## 保存形式と参照管理

テーマ定義は、新設する`theme.ini`へ保存します。標準配置は`global.ini`と同じ設定ディレクトリの`$XDG_CONFIG_HOME/elder-terms/theme.ini`です。複数のテーマをこの一ファイルで管理し、編集画面はアプリケーション設定の「テーマ」タブに置きます。

| ファイル | 保存する内容 |
| --- | --- |
| `global.ini` | アプリケーション設定とグローバル既定値 |
| `theme.ini` | テーマの参照用ID、表示名、各テーマが明示した設定項目 |
| 接続INI | 選択したテーマの参照と、接続で明示した設定項目 |

読み込み側にはテーマファイルのパスを渡せるようにします。標準ではグローバル設定と同じディレクトリから解決し、試験や独立した設定環境では両方のパスを指定できる構成です。接続INIを置いたディレクトリへ暗黙に切り替えたり、試験で実ユーザーのテーマを読んだりしません。

`theme.ini`が未作成ならテーマ一覧は空です。テーマを選んでいない接続は従来どおり動作し、参照がある接続では後述の未解決扱いになります。読み取り失敗や不正なINIを、空の一覧として上書きしないことも条件です。次はINI内の形式案で、現在のAPIや対応済みの設定ではありません。

```ini
; theme.ini
[theme.theme-01]
name=赤テーマ

[theme.theme-01.general]
exterior_background=#7A2222
background=#281818
```

```ini
; connection.ini
[general]
theme=theme-01
```

`theme-01`は参照用IDの例です。利用者が名前に空白や日本語を使っても、INIの区分名や接続参照へ直接埋め込まない形式にします。保存する値の型は元の設定定義から決め、文字列へ変換して独自の型判定を行いません。

## 二つの設定ファイルの保存

保存操作では、アプリ設定、グローバル既定値、テーマ一覧の下書きを先にまとめて検証します。書き込むのは変更があるファイルだけです。テーマだけの変更なら`theme.ini`だけを更新し、`save_global_settings()`や`save_new_window_connection()`による通常設定の保存では`theme.ini`を触りません。

一時ファイルを作って置き換える既存の方式を、各ファイルの保存へ使います。二つのファイルを順に置き換えても、二ファイル全体の一括確定にはなりません。そのため、両方を変更した場合は保存結果を別々に保持し、成功したファイルと失敗したファイルを画面で区別する初期案です。

一部だけ保存できた場合は画面を閉じず、成功分は保存済み、失敗分は未保存として残します。再試行は未保存分を対象とし、その後のキャンセルは未保存の編集だけを破棄する契約です。保存に失敗したファイルは直前の内容を保ち、すべて成功した場合だけ全体の保存完了を表示します。

保存後にランチャーへ反映する値は、実際に保存された`global.ini`と`theme.ini`の組合せから作ります。未保存のグローバル値を、保存済みテーマの継承値として適用しません。外部編集との競合もファイルごとに確認します。

## テーマの参照管理

テーマ名の空欄と重複名は編集画面で検出する初期案です。改名ではIDを変えず、参照中の接続INIを書き換えません。使用中のテーマは、その接続を一覧に示し、参照を外してから削除する方針とします。保存済みの接続だけでなく、ランチャーで編集中の参照も確認します。

外部編集などで参照先がなくなった場合は、「テーマ未解決」として参照IDを保持します。起動前に参照を修正するか、「なし」を明示的に選ぶ初期案です。テーマ名とIDの重複、未登録の項目、不正な型も診断へ含めます。

既存の`retain_invalid`対象の値は、そのエラーを継承元ごと保持します。テーマを挟んでも、無効な接続設定を有効扱いにしないことが条件です。

## アプリケーション設定の画面

アプリケーション設定のタブ構成は次のとおりです。

| タブ | 編集する内容 |
| --- | --- |
| アプリケーション | 言語、起動方法、アプリのホットキー、新しいウインドウなどの既存設定 |
| 接続の既定値 | 現在ランチャー下部から開いている既定値エディター |
| テーマ | テーマの一覧、名前、定義する項目、継承した結果のプレビュー |
| 情報 | 既存のバージョンなどの表示 |

タブを切り替えても編集内容を保ち、保存とキャンセルの操作は画面全体で共用します。保存は、どの編集タブにも入力エラーがなく、未保存の変更があるときに可能とします。一部だけ保存できた場合は、「二つの設定ファイルの保存」で定めたファイルごとの結果に従います。情報タブへ移っただけで変更を失ったり、他のタブの不正入力を保存したりしない構成です。表示言語変更時の再起動案内やホットキーの再登録は、該当する通常設定の保存が成功した後に行います。

テーマタブは、左側に名前の一覧と新規・複製・削除、右側に名前と項目の編集を置く案です。既存の設定エディターをテーマ用の表示で再利用し、各項目を「テーマで指定する」か「グローバル既定値を継承する」か選べるようにします。初期状態では項目を一つも明示しません。画面に継承値を表示しただけで、全項目がテーマへ保存されることを防ぎます。

プレビューは、現在のグローバル既定値に編集中のテーマを重ねた表示です。赤テーマならタイトルバーと本文背景を同時に確認できる例を用意します。プレビューの変更だけでは、実行中の接続や保存済みの設定へ反映しません。

新しい導線で既定値を編集・保存できる段階で、ランチャー下部の既定値ボタンと専用ダイアログを削除します。削除を確認する一時テストは、共通条件に従ってRED・GREEN確認とコミットを行い、その後に撤去します。新しい画面から既定値を変更できる機能テストは、継続して実行する対象です。

## 接続からの選択と反映時期

接続設定の一般ページに「テーマ」を追加し、「なし」と登録済みテーマを選べるようにします。初期値は「なし」です。各項目には、グローバル既定値、テーマ名、接続での指定を区別できる表示を付けます。テーマ変更後も接続で指定した項目は残るため、必要な項目だけ明示指定を解除できる構成です。

保存済みテーマの変更は、次の接続読み込み・新規起動で反映します。ランチャーで開いている接続設定は、保存後に継承値を更新する対象です。接続の未保存編集と不正入力は保持します。下書きと適用済み状態で別のテーマを選んでいる場合、継承値もそれぞれの選択から作り直す必要があります。

起動中の端末や転送画面へ、テーマ編集だけで変更を一斉配信する機構は今回追加しません。実行中の設定画面を開く際に最新のテーマ一覧と定義を読み、選択結果は既存の適用・保存操作で反映する初期案です。通信先など実行中に変更できない項目は、現在の制限と再接続の規則に従います。編集中に外部で定義が変わった場合は、保存時の差分確認で変更の消失を防ぎます。

最初の成果物は、`global.ini`、`theme.ini`、接続INIを分けて読み込むC++ドライバーです。グローバル、赤テーマ、接続の各入力から実効値と継承元を出力します。テーマファイルの未作成・読み取り失敗、テーマなし、部分定義、接続の上書き、同値の明示指定、明示解除、起動時設定による参照変更をRED確認してから実装します。

アプリケーション設定へ既定値エディターとテーマタブを統合します。成果物は、テーマの新規作成から項目の指定と解除、プレビュー、保存・再読み込みまでを操作できる画面です。新しい画面で既定値を保存できることを確認してから、旧ボタンと専用ダイアログを削除します。

## 段階3：接続のテーマ選択と継承元の表示を完成させる

接続の一般ページへ選択欄を追加し、テーマの切替と「なし」への復帰を実装します。継承値の表示、個別の上書き、未保存編集、実行中の適用も対象です。テーマ名の変更と複製は、参照IDを使って試験します。

完了条件は、INIを手で編集せずに赤テーマを二つの接続から参照できることです。一方の接続で背景だけを上書きし、テーマ変更後もその指定が残ること、解除するとテーマの背景へ戻ることを画面で確認します。

## 最終完了条件

1. 一部の設定だけを持つ名前付きテーマを`theme.ini`へ作成・保存し、複数の接続から参照できる。通常設定は`global.ini`に保持する。
2. グローバル既定値、選択テーマ、接続設定の順に明示値を適用する。テーマ未指定では現在の動作を保つ。
