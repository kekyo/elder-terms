# plan31 ドッキングした端末のタイトルと動作状況をタブに表示する

複数の端末を一つのウインドウにまとめたとき、左のタブ一覧で各端末のタイトルと受信状況を確認できるようにします。例えば端末Bを操作中にAがデータを受信すると、帯が流れるのはAのタブだけです。途中でAを選ぶと、上部のタイトルバーにも同じ位置から帯の続きが見えます。端末のベルを表す制御文字（BEL）を受信したときは、その端末のタブとタイトルバーの背景が短く明滅します。

2026年11月27日作成。調査対象は`develop`の`37faf4c4`です。

## 31.1 各タブにタイトルバーの色とタイトルを表示する

現在のタブ名は、タブを作った時点の接続名です。接続アイコンはタイトルバーに連動し、長い名前にはGTKの末尾省略を使っています。閉じるボタン（×）は透明度で隠しているため、ポインターが行の外にあってもボタンの幅が残ります。[タブ作成時に渡す接続名](../../../elder-terms-terminal/src/main.cpp#L2191)・[タブ行の構築とホバー時のスタイル](../../../elder-terms-terminal/src/terminal-tabs.cpp#L508)

新しいタブ名の取得元は、端末ごとのタイトルバーにあるラベル`header_title_label`です。ここにはシェルが指定したタイトルと接続名に加え、切断時に付ける表示も含まれます。タブを作った時点の全文を行に表示し、その後の変更も同じ行に反映します。[タイトルと接続名の組み立て](../../../elder-terms-terminal/src/main.cpp#L571)・[切断表示を含むタイトルの更新](../../../elder-terms-terminal/src/main-window.cpp#L880)

| タブの状態 | 表示と操作 |
| --- | --- |
| 通常 | 接続アイコンの右から行の右端までをタイトルに使います。収まらないときだけ末尾を「…」で省略します。 |
| ホバー | ポインターを重ねた行の右端に×を表示し、その間だけボタンの幅とクリック領域を確保します。アイコンの位置と行の高さを保ち、タイトルの幅を縮めます。ポインターを×の上に移してもボタンを表示し続けます。 |
| 選択中 | 行の内側に細い縦線を表示します。同じ背景色の端末が並んでも、ホバーやBELの明滅中でも入力先を見分けられます。 |

ウインドウのタイトルバーや枠と各タブの輪郭を区別できるように、一覧の四辺に2論理ピクセルの余白を取ります。隣り合うタブの間隔も合計2論理ピクセルです。

各タブの基準色には、接続ごとに適用された外枠の背景色`[general] exterior_background`を使います。色の指定がないときは、その端末のタイトルバーを描くGTKテーマの背景を基準にします。Oklchは色を明度・彩度・色相で表す方式です。配色の初期案では、色相を保ち、通常時の明度を元の94%、彩度を85%に抑えます。ホバー時は明度を100%に戻し、彩度は85%に保ちます。[外枠への色の適用](../../../elder-terms-terminal/src/main-window.cpp#L1248)・[既存のOklch変換](../../../shared/include/elder-terms/terminal-color-filter.h#L19)

設定例の赤テーマを既存の関数で変換すると、タイトルバーの`#7A2222`に対し、タブは通常時が`#6C2422`、ホバー時が`#732A28`です。文字と×には、変換後の背景に対して読みやすい方の白または黒を選びます。この配色は試算値です。係数は実際の端末で見比べて決めます。[赤テーマの設定例](../configuration.md#名前付きテーマ)・[背景に合わせた文字色の選択](../../../shared/src/connection-runtime/widget-background.cpp#L174)

この段階の完了条件は、異なる配色の2端末をドックし、未選択の行にもその端末の色と最新タイトルが出ることです。幅の境目にあたるタイトルを使い、通常時は全文が収まり、ホバー時だけ「…」と×が現れることを確かめます。未選択行の×を押した後も、操作中だった端末で入力を続けられることを確認します。[GTKの末尾省略](https://docs.gtk.org/gtk3/method.Label.set_ellipsize.html)・[未選択タブを閉じる既存試験](../../../elder-terms-terminal/tests/terminal-docking-group.sh#L110)

## 31.2 受信グラデーションとBELの進行状態を共有する

現行実装は未選択の端末でもタイトル変更とBELを処理します。受信の帯とBELの明滅の状態を持つのは、各端末のタイトルバーです。ドックすると上部には選択中のタイトルバーだけが表示され、非表示になったタイトルバーの演出はリセットされます。そのため一覧からは、未選択の端末にデータやBELが届いたことが分かりません。[タイトル変更とBELの処理](../../../elder-terms-terminal/src/terminal-runtime.cpp#L977)・[表示するタイトルバーの切り替え](../../../elder-terms-terminal/src/terminal-tabs.cpp#L166)・[非表示時の演出停止](../../../shared/src/connection-runtime/titlebar-effects.cpp#L130)

受信の帯の周期とBELの開始時刻を記録する既存の`TitlebarEffectState`を、端末ごとに一つ持たせます。タイトルバーとタブ行が参照するのは、同じ時刻にこの状態から求めた帯の位置と明滅の強さです。背景に効果を重ねる描画処理も共用し、表示先ごとの幅に合わせて帯を描きます。[演出の状態と時刻](../../../shared/src/connection-runtime/titlebar-effect-state.h#L14)・[背景と効果の描画](../../../shared/src/connection-runtime/titlebar-effects.cpp#L79)

受信とBELにはそれぞれの接続で選んだ「無効・弱・中・強」を適用します。帯が一度通過する時間は1.2秒です。帯の移動中に通常データが届けば、その周期を終えてからもう一度帯が流れます。BEL単独で始まる演出はフラッシュだけです。すでに流れている帯は元の周期で進みます。音を鳴らす回数は、有音設定で1回のBELにつき1回です。最小化中やGTKのアニメーションが無効なときは演出の更新を止めます。[受信とBELの判定](../../../elder-terms-terminal/src/main-window.cpp#L1304)・[受信周期とフラッシュ](../../../shared/src/connection-runtime/titlebar-effect-state.cpp#L13)・[視覚通知と音の呼び出し](../../../elder-terms-terminal/src/main.cpp#L2090)

この段階の完了条件は、Bを選んだままAに通常出力とBELを別々に送り、Aの行で帯とフラッシュを動画で見分けられることです。途中でAを選び、帯が行の中央を通るときに上部のタイトルバーでも中央を通ることを同じフレームで照合します。接続ごとの強度、BEL単独の受信、有音設定での再生回数は既存のタイトルバー試験と合わせて確認します。[タイトルバー通知の動画試験](../../../elder-terms-terminal/tests/titlebar-effects.test.ts#L206)

## 31.3 変更された長いタイトルを末尾まで流す

タイトルが変わったら、GTKで文字を配置するPangoを使って全文の描画幅を測ります。その時点のタイトル欄に収まれば、すぐに全文が読めます。横に流す対象は、表示幅を超える新しいタイトルだけです。先頭で短く静止してから、末尾が読める位置まで一定速度で文字だけを流します。末尾でも少し静止し、次の変更がなければ通常の省略表示に戻します。[Pangoの描画幅の計測](https://docs.gtk.org/Pango/method.Layout.get_pixel_size.html)

例えばタイトルAを流している間にB、Cの順で変更が届いても、Aを末尾まで表示します。次回分として保持するのは最後に届いたCだけです。Aが終わるとCを先頭から表示し、Cが収まる幅ならそのまま静止します。上部のタイトルバーとタブのツールチップに反映するのは、スクロール中もその時点の最新の全文です。

ホバーで×が現れたときや利用者が一覧の幅を変えたときは、文字の現在位置を保ちながら残りの移動距離を調整します。スクロールの速さと両端で待つ時間は、実際のタブで読みやすさを確かめて決めます。

受信の帯とタイトル変更時のスクロールは別々の動作です。帯を無効にしても、長いタイトルに変われば文字が流れます。GTKのアニメーション設定が無効なときのタブは静止表示です。収まらない分は末尾で省略し、ツールチップに最新の全文を載せます。

この段階の完了条件は、長いタイトルを続けて送った動画で、最初のタイトルの末尾に続いて最新タイトルの先頭と末尾が読めることです。あわせて、短いタイトルや同じ文字列の再通知、ホバーや一覧幅の変更だけでは新しいスクロールが始まらないことを確かめます。録画では文字の移動中も接続アイコンと×の位置が安定し、タブの選択やドラッグ分離ができることを確認します。[タブの選択とドラッグの操作試験](../../../elder-terms-terminal/tests/terminal-tab-feedback-x11.sh)

## 31.4 接続中の全種類の端末をタブに追加する

ローカル端末を2枚まとめたウインドウに、CP932のTelnet端末を追加できない事例を受け、対象をローカル、SSH、Telnet、シリアルの4種類に広げます。移動先にすでにタブがあっても、異なる種類の端末を接続したまま追加できることが目標です。

完了条件は、ドロップ後も元のシェル、ネットワーク接続、シリアルポートで送受信できることです。Telnetの制御メッセージや日本語の文字が移動の前後に分かれて届いた場合は、応答と表示を確かめます。シリアルでの確認項目は、移動後の通信速度の変更、BREAK送信、移動中に下がったキャリア信号の検出です。タブをまとめてもう一度移した後も、同じ接続先と送受信できることを確認します。[同じ接続で2回ドッキングする試験](../../../elder-terms-terminal/tests/terminal-docking-stream.sh)・[シリアルポートの引き継ぎ試験](../../../elder-terms-terminal/tests/cpp/boxrig-serial-transport-test.cpp)

## 計画全体の完了条件

各段階で利用者から見える動作を先に試験にし、変更前の失敗と実装後の成功を確かめてからコミットします。最後の動作確認に使うのは、一つのウインドウにまとめた2端末です。受信、BEL、タイトルの連続変更を順に起こし、通知元の端末と実際に動いた行を動画で照合します。録画を目視し、ドックと分離、未選択行を閉じる操作まで確かめます。各段階の完了条件を満たし、`make build`が警告なく成功して`make test`で全体試験が通れば実装完了です。

## 実装と検証の結果（2026年11月27日）

赤と青の端末を並べて見比べ、タブの明度と彩度には31.1の係数を採用しました。赤のタブの実測値は通常時が`#6C2422`、ホバー時が`#732A28`です。通常時にぎりぎり収まるタイトルでは、×が現れたときだけ末尾が「…」に変わります。録画では、赤の設定を変えると青のタイトルバーのボタンまで赤くなる問題も見つかりました。ボタンの色を端末ごとに適用し、赤の設定を変えても青のボタンが元の色を保つことを試験に加えました。

未選択の赤い端末に出力を送ると、そのタブで受信の帯が流れます。途中で赤に切り替え、帯がタブと上部のタイトルバーの中央を同時に通るフレームを確認しました。青を選んで再び赤にBELを送ると、赤い行だけが明滅しました。[受信とBELを録画するGTK試験](../../../elder-terms-terminal/tests/cpp/terminal-tab-titlebars-test.cpp)

長いタイトルは先頭で0.30秒待ち、毎秒80論理ピクセルで末尾まで流れます。末尾を0.45秒表示し、次の更新があればそのタイトルに移り、なければ省略表示に戻ります。3件続けて更新した録画では、最初のタイトルの末尾と最後のタイトルの両端をフレームごとに照合しました。実際のローカル端末では、文字が流れている行もドラッグで分離できます。再ドックして未選択行の×を押した後も、選択中のシェルは入力を受け付けました。

31.1から31.3の実装後、`make build`は警告なく完了しました。全体試験に使った`VITEST_MAX_WORKERS=1 make test`の終了コードは0です。Mesonは324件、4つのワークスペースのVitestは計1,252件が成功しました。環境条件などで対象外となった試験はMesonが2件、Vitestが11件です。X11とWaylandのドッキング試験、端末の入出力遅延試験、NFSの転送試験も通りました。

31.4では、ローカル端末2枚のウインドウにCP932のTelnet端末をドロップし、同じ接続で「日本」というタイトルを受信して日本語も送信できました。その3枚を別のウインドウにまとめて移した後も送受信が続きました。シリアルの試験に使ったのは疑似ポートです。ドロップ前にデバイスのパスを取り除いても、開いていたポートで通信を続けられました。追加対応後の`make build`と`make test`の終了コードはともに0です。Mesonは329件、Vitestは計1,252件が成功し、それぞれ2件と11件がスキップされました。
