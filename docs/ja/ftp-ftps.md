## FTP/SFTPの詳細

### FTPでTLSを使用する (FTPS)

[FTPS](https://everything.curl.dev/ftp/ftps.html)を使用するには、FTPタブの「暗号化」で「FTPS（明示的TLS）」または「FTPS（暗黙的TLS）」を選択して下さい。INIでは `[ftp]` の `tls_mode=explicit` または `tls_mode=implicit` に相当します。明示的FTPSはAUTH TLSで暗号化へ移行し、既定ポートは21です。暗黙的FTPSは接続直後からTLSを使用し、既定ポートは990です。グローバル設定から継承した値を含め、明示指定されたポートが優先されます。両方式でActive／Passive、IPv4／IPv6、データ接続でTLSセッション再利用を要求するサーバーに対応します。既定では制御・データ接続の両方でTLS 1.2以上を必須とし、証明書と接続先名の検証に失敗した場合は拒否します。独自CAは `ca_file=/absolute/path/company-ca.pem` で指定し、空の場合はシステムCAを使用します。平文FTPへ自動で切り替えることはありません。

Active FTPSにはlibcurl 8.0.0以降が必要です。Debian 12の7.88.1など、それより古い対応版には[Activeデータ接続のTLS不具合](https://curl.se/ch/8.0.0.html)があるため、Activeでは接続前に拒否します。この環境ではPassiveを選択するか、libcurlを更新して下さい。

Active FTP／FTPSでは、[データ接続の開始処理にある競合](https://github.com/curl/curl/blob/curl-8_14_1/lib/ftp.c#L3647)を避けるため、操作ごとに制御接続を新しく開きます。次の操作を開始する前に、前の制御接続を閉じます。libcurl 8.9.0未満でTLS 1.3を許可する場合は、FTPSのPassiveでも制御接続を新しく開きます。旧版ではアップロード終了時に次のデータ接続に必要なセッションチケットを失うことがあるためです（[上流の報告](https://github.com/curl/curl/issues/4654)、[8.9.0の終了処理改善](https://curl.se/ch/8.9.0.html)）。新しいlibcurl、または最大TLS版を1.2以下に明示したPassive接続では再利用を維持します。

FTPタブではTLSバージョンの上下限、AUTHの優先順、互換性、CA証明書、暗号、証明書検証の失敗時の方針を設定できます。下へスクロールしてTLSの詳細を表示し、「適用」で保存してから接続して下さい。

各項目は接続の既定値を継承するか、接続固有の値を指定できます。CAと暗号の欄は「独自指定」で入力し、CAはファイル選択も使用できます。「システムのCA証明書」または「ライブラリの既定値」を明示的に選ぶと、継承された独自値を既定の動作で上書きできます。不正な形式や上下限の逆転がある間は適用できません。暗号の対応可否は接続時に確認します。接続中の転送ウィンドウではTLS設定は読取り専用です。保存済み接続を編集して再接続すると反映されます。

FTPタブのTLS設定は、以下のINIキーに対応します。

| キー | 既定値 | 指定可能な値 |
| --- | --- | --- |
| `tls_min_version` | `1.2` | `1.0`、`1.1`、`1.2`、`1.3` |
| `tls_max_version` | `default` | `default`（バックエンドの上限）、または同じバージョン値 |
| `tls_auth_order` | `tls` | `tls`、`ssl`、`default`（明示的FTPSのみ） |
| `tls_compatibility` | `standard` | `standard`、`openssl_legacy` |
| `tls_cipher_list` | 空 | TLS 1.2以前のOpenSSL暗号式 |
| `tls13_cipher_list` | 空 | TLS 1.3暗号名のコロン区切り |

バージョンを固定するには上下限を同じ値にします。例えば `tls_min_version=1.0`、`tls_max_version=1.0`、`tls_compatibility=openssl_legacy` を指定すると、導入されたOpenSSLで対応可能な場合にTLS 1.0のみを使う接続になります。互換設定は当該接続に限り[OpenSSLのセキュリティレベル0](https://docs.openssl.org/3.0/man3/SSL_CTX_set_security_level/)を明示的に選びます。証明書検証や他の接続の条件は変わりません。標準設定ではバックエンドのポリシーを維持するため、バージョン範囲に含めても旧TLSが拒否される場合があります。

SSLv2／SSLv3には対応しません。AUTH SSLはFTPコマンドの選択であり、SSLv3の指定ではありません。暗号式と旧TLS互換にはOpenSSL版libcurlが必要です。全て未知の暗号名や未対応設定では接続に失敗します。匿名認証・非暗号化の暗号スイートは除外します。OpenSSL 3.5で追加された[整合性保護のみのTLS 1.3スイート](https://docs.openssl.org/3.5/man3/SSL_CTX_set_cipher_list/)も拒否します。暗号式内の `@SECLEVEL` は受け付けず、互換設定で指定します。バックエンドの制約は[libcurlのTLSバージョン指定](https://curl.se/libcurl/c/CURLOPT_SSLVERSION.html)と[暗号指定](https://curl.se/libcurl/c/CURLOPT_SSL_CIPHER_LIST.html)を参照して下さい。

### FTPSの証明書エラー

「証明書検証の失敗時」で「接続を拒否」（既定）または「オーバーレイで確認」を選択できます。INIではそれぞれ `certificate_error_action=reject` と `certificate_error_action=prompt` に相当します。確認を選ぶと、接続先とポート、制御／データの区別、検証理由、証明書の所有者・発行者・有効期間、SHA-256フィンガープリント全体をオーバーレイに表示します。既定の操作はキャンセルです。Escやウィンドウを閉じる操作でも接続を拒否します。

例外の許可は、その接続ウィンドウ内の表示された証明書と検証失敗だけに適用します。接続ファイルやシステムの信頼ストアには保存しません。別の検証失敗や証明書変更時には再確認し、新しいウィンドウには許可を引き継ぎません。例外が有効な間はステータスバーに表示します。正常な証明書では確認を表示しません。

最初のログインは許可後に継続できます。ファイル操作中に証明書エラーが発生した場合、その操作は許可後も失敗として扱うため、利用者が明示的に再試行して下さい。アップロード・名前変更・削除を自動で繰り返すことはありません。確認の対象は、発行者の信頼、有効期間、接続先名に関する失敗です。それ以外の証明書エラーは拒否します。証明書の許可によってTLSバージョン、暗号、暗号ポリシー違反を緩和することもありません。古いサーバーに必要な場合は、独立した旧TLS互換設定を使用して下さい。

証明書確認には、libcurlとアプリケーションが同じバージョンのOpenSSLを使用する必要があります。他のTLSバックエンドでは既定の拒否設定を使用できますが、この確認方式は使用できません。この制約は[libcurlのTLSコンテキストコールバック](https://curl.se/libcurl/c/CURLOPT_SSL_CTX_FUNCTION.html)がバックエンド固有のコンテキストを渡す仕様によります。

### FTPのデータ接続

FTPSでは制御接続も暗号化されるため、ファイアウォールやNAT機器がFTPコマンドを読んでデータ用ポートを判断できません。必要に応じて、サーバーのPassive用ポート範囲やクライアントへのActive接続経路を明示的に設定して下さい。[FTPSの接続解説](https://everything.curl.dev/ftp/ftps.html)も参照して下さい。

FTPは制御接続を使用し、ディレクトリ一覧またはファイル転送ごとに別のデータ接続を作成します。「データ接続モード」では、そのデータ接続をどちら側から開始するかを選択します。

- 「Passive（推奨）」: elder-termsから、サーバーが選択したポートへ接続します。最初に `EPSV` を試し、IPv4でサーバーが `EPSV` に対応していなければ `PASV` へフォールバックします。二つの接続がどちらもクライアントからのアウトバウンド接続になるため、通常はクライアント側のNATやファイアウォールを越えやすい方式です。`PASV`では、[RFC 2577](https://www.rfc-editor.org/rfc/rfc2577)のFTPセキュリティ指針に従って通知されたホストアドレスを無視し、制御接続先と同じホストを使用します。
- 「Active」: elder-termsがローカルポートで待ち受け、サーバーから接続を受けます。最初に `EPRT` を試し、IPv4では `PORT` へフォールバックします。サーバーからクライアントへのインバウンド接続が到達する必要があるため、ファイアウォールやNATの設定が必要になる場合があります。制御接続先とは異なるホストからのデータ接続は拒否します。

`EPSV`と`EPRT`は[RFC 2428](https://www.rfc-editor.org/rfc/rfc2428)で定義されたIPv4/IPv6対応の拡張コマンドです。`PASV`と`PORT`は従来のIPv4用フォールバックです。これらはPassiveとActiveの中で使用するコマンドの違いであり、追加のデータ接続モードではありません。IPファミリーはサーバーアドレスの名前解決時に決まります。プロキシ経由の接続やデータポート範囲の指定は、elder-termsの独立した選択肢には含まれません。

### FTP操作の順序と互換性

ディレクトリノードを開く操作を含むすべてのリモート操作は非同期に開始するため、GTKウインドウの応答は維持されます。各FTPウインドウは専用の認証済みセッションを持ち、可能な場合は制御接続を再利用します。操作はFIFO順に待機し、一つの操作はデータ転送とサーバーの最終完了応答まで順番を保持します。そのため、別の操作中に要求したディレクトリ取得は、制御通信を混在させず待ち行列に入ります。

elder-termsはバイナリ転送モードを選択し、サーバーが[RFC 3659](https://www.rfc-editor.org/rfc/rfc3659)の標準化された `MLST` / `MLSD` 拡張を通知した場合は `MLSD` の一覧を優先します。古いサーバーでは、一般的なUnix形式とDOS形式の `LIST` 出力へフォールバックします。サーバー固有の特殊な `LIST` 形式は認識出来ない場合があります。また、FTPではSFTPが持つシンボリックリンク、POSIXパーミッション、タイムスタンプ更新の各機能を使用出来ません。
