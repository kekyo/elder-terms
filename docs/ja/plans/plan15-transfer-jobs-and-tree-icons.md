## ツリーノードの表示

左右のローカル・リモートツリーで、名前の前に同じ寸法のアイコンを置きます。展開矢印の操作領域、行高、複数選択、ドラッグ開始位置は既存の操作を保ちます。初期寸法の候補は16論理ピクセルです。表示倍率に合わせた描画も検証します。

| 分類 | 既存Material資産の候補 | 判定例 |
| --- | --- | --- |
| ディレクトリ | `file/folder` | 通常のディレクトリ |
| SMB共有 | `file/folder_shared` | SMBクライアントが共有ルートと通知した項目 |
| NFS公開ルート | `device/storage` | plan17が公開ルートと通知した項目 |
| 一般ファイル | `editor/insert_drive_file` | 未知の拡張子、拡張子なし |
| 文書・PDF | `action/description`、`image/picture_as_pdf` | `.txt`、`.md`、`.pdf` |
| ソースコード | `action/code` | `.c`、`.h`、`.cpp`、`.ts`、`.json`など |
| 画像・音声・動画 | `image/image`、`image/audiotrack`、`av/movie` | `.png`、`.jpg`、`.mp3`、`.wav`、`.mp4`など |
| 圧縮ファイル | `content/archive` | `.zip`、`.tar`、`.tar.gz`、`.7z`など |
| シンボリックリンク | `content/link` | リンク自身の種別。リンク先は追加取得しない |

拡張子は大文字・小文字を同じ扱いにし、複合拡張子は長い一致を優先します。未知の項目も必ず一般アイコンで表示します。アイコンのために内容の読み込みやネットワーク通信は行いません。

共有やexportsは、パスの深さだけでは通常フォルダーと区別できません。`RemoteFileAttributes`へ表示上の役割を追加し、種別はディレクトリのまま保ちます。役割は表示用であり、変更可否は引き続き`path_capabilities()`で判断します。Material資産は元ファイルを編集せず利用する方針です。通常行・選択行・暗い背景のすべてで輪郭が見える色を選びます。

## 転送ジョブの単位と責任

ジョブは「利用者が一度に指示した転送」を表します。複数ファイルやディレクトリを選んでも一つのジョブとし、内部の項目数と進捗を表示します。プロトコルのクライアント、ジョブの状態管理、画面表示を分け、共通モデルにGTKウインドウへの生ポインターを持たせません。

ジョブにはID、接続の識別子と世代、方式、方向、転送元・先、開始・終了時刻、進捗、結果、キャンセル手段を持たせます。IDは再接続後も古い通知と区別できる値です。認証情報は表示用データや履歴に含めません。

| 状態 | 表示と操作 |
| --- | --- |
| 待機 | 接続の実行枠を待つ。取り消し可能 |
| 調査中 | 再帰探索中。件数・総サイズが未確定であることを表示 |
| 転送中 | 確定済みの総量があれば割合を表示。不明なら転送済みバイト数と件数を表示 |
| 判断待ち | 上書き、スキップ、失敗後の再試行などの入力を待つ |
| 中止処理中 | 通信と一時ファイルの後始末を待つ。後始末の終了まで「中止済み」にしない |
| 完了・失敗・中止済み | 成功数、スキップ数、失敗箇所、未処理数、残った一時ファイルを結果として保持 |

最初は現在の一接続一転送を維持します。キューを追加する段階で、待機ジョブの条件を実行直前に再確認します。再試行は失敗した操作の再試行と、終わったジョブを新しいIDでやり直す操作を区別し、転送途中からの再開は保証しません。

総バイト数が不明なHTTP受信や探索中のディレクトリでも、0%や100%を誤表示しない契約にします。現在のエンジンの戻り値は`void`なので、全項目スキップを無条件の成功件数に含めないよう、終了結果の集計も追加します。

## ジョブ一覧の配置案

| 案 | 配置と操作 | 利点 | 制約 |
| --- | --- | --- | --- |
| A・推奨 | 転送画面の下部に高さを変えられる折り畳み一覧。閉じていても件数と進捗の要約を残す | 左右のツリーと転送先を見ながら経過を追える。既存の単独ウインドウに収まる | 小さい画面ではツリーの高さが減る |
| B | 画面右側の開閉パネル | 行ごとにエラーや操作を置きやすい | 左右ツリーの横幅が減り、長いパスが読みにくくなる |
| C | 独立したジョブウインドウ | 多数のジョブを広い画面で確認できる | 全接続を集約するなら別プロセス間の通信と寿命管理が必要 |
| D | ヘッダーの進捗ボタンから開くポップオーバー | 普段のツリー面積を保てる | 長時間の監視と多数の失敗の確認には向かない |

A案の初期表示は、方向、対象名、状態、進捗、中止ボタンをまとめた一行です。選択した行を展開すると転送先と結果の詳細を確認できます。実行・判断待ち・失敗の行を優先し、終了済みの履歴は手動で消せる構成です。履歴はそのプロセスの実行中だけ保持し、再起動後のジョブ復元は今回の対象に含めません。

推奨する所有単位はウインドウです。ツリー型転送は転送ウインドウ、X/Y/ZMODEMは端末ウインドウに同じ一覧部品を置きます。すべての接続を一つの一覧へ集めるC案は別の選択肢として残します。タイトルバーの演出とは独立した表示であり、ジョブ継続のためにタイトルを更新する設計にはしません。

画面の折り畳みではジョブを継続します。所有ウインドウを閉じると待機ジョブを取り消し、実行中の処理と後始末を終了させてから接続を破棄する方針です。ブラウザー操作を転送中も許す段階では、読み取り要求を接続側で直列化し、同じ転送先への削除や名前変更を禁止します。

## 段階1：既存ツリーへアイコンを表示する

通常フォルダー、ファイル分類、SMB共有の表示を先に完成させます。役割の型にはNFS公開ルートも含めます。NFSの通信実装はplan17の対象です。

テストでは、名前・種類と見た目の対応、選択後も読める表示、展開矢印、クリック・複数選択の機能を確認します。SVGの存在確認だけを合格条件にしません。成果物は既存SFTP・SMBを実際に操作できる転送画面です。完了条件は、通常項目と共有ルートを見分けられ、転送とツリーの操作が通ることです。

## 段階2：現在の一件の転送をジョブで動かす

既存の進捗オーバーレイを表示先として残し、実行、キャンセル、判断待ち、終了結果をジョブから通知する構成に置き換えます。単一転送の動作を観測できるC++ドライバーと既存GUIテストで、状態の順序、例外、ウインドウ破棄、二重終了を検証します。

この段階では同時実行を増やしません。完了条件は、現在の操作でジョブが一つ作られ、成功・スキップ・失敗・中止が正しく集計されることです。

## 段階3：採用した一覧を表示し、待機キューを加える

配置案を選んだ後、ジョブ一覧と折り畳み時の要約を統合します。推奨A案は、既存のオーバーレイを置き換えても判断待ちの入力を操作できる構成です。その後で同じ接続への追加転送をキューに入れます。

一覧で中止したジョブだけが止まること、探索中にも中止できること、判断待ちで後続処理が割り込まないことを確認します。切断後の待機ジョブは自動実行せず、再接続後の再試行対象として明示します。完了条件は、二つ以上のジョブを順に実行し、画面を操作しながら状態と結果を追えることです。

## 段階4：端末内のファイル転送を共通モデルへ接続する

X/Y/ZMODEMの転送要求と進捗をアダプターでジョブへ接続します。バイトストリームの占有、端末入力の抑止、自動ZMODEM開始は既存runnerの責任とし、共通化するのはジョブの状態・結果・表示です。テキスト送信や一般的な端末コマンドのジョブ化は含めません。

端末ウインドウでも開始・進捗・中止・終了を確認できる状態でコミットします。完了条件は、X/Y/ZMODEMの各方式が共通一覧に現れ、転送終了後に同じ端末セッションへ戻れることです。

## 段階5：寿命・表示・全体検証

既存の[file-transfer-contract-test.cpp](../../../elder-terms-terminal/tests/cpp/file-transfer-contract-test.cpp)、[sftp-transfer-engine-test.cpp](../../../elder-terms-terminal/tests/cpp/sftp-transfer-engine-test.cpp)、[file-transfer-window-lifetime-test.cpp](../../../elder-terms-terminal/tests/cpp/file-transfer-window-lifetime-test.cpp)へ検証を追加します。GUIでは各転送方式、X/Y/ZMODEM、未知の総量、ゼロバイト、全スキップ、切断、再接続、終了直前のキャンセルを確認します。
