# plan21：ドラッグ中の通常選択・ブロック選択の切替

作成日：2026年11月2日

状態：2026年11月5日に段階1の再現試験と公開APIの調査を実施しました。画面外の開始点を保持して形状を変更する公開APIが不足しているため、段階1の完了条件は未達です。段階2以降は依存待ちです。

## 目的と操作条件

左ボタンでコピードラッグしている間に、Ctrlの現在の状態を選択モードへ反映します。Ctrlなしは通常選択、Ctrlありはブロック選択です。初期モードは現在と同様に、左ボタン押下時のCtrl modifierで決定します。初期モードの決定に、Ctrlの変化を待つ処理は加えません。

開始後に切り替えるのは、Ctrlの状態が変わった後にポインターが実際に移動したときだけです。初期値の設定と、ドラッグ中のモード変更を別の処理として扱います。

Ctrlの押下・解放だけでは、選択範囲、見た目、コピー内容を変更しません。同じドラッグの開始点を保持して、次のマウス移動で現在の終点までを新しい形状として再計算します。

共通条件は[plan15](plan15-transfer-jobs-and-tree-icons.md)に従います。実装順は、ポインターとCtrlクリックを変更する[plan20](plan20-hyperlink-recognition-and-hover.md)の後です。統合後に本planの操作を検証します。

## 現在のコード

[terminal-runtime.cpp](../../../elder-terms-terminal/src/terminal-runtime.cpp)では、左ボタンの押下時に`boxrig_ui_selection_options.shape`をCtrlの状態から選びます。選択開始を待つ`pending`と、開始後の`dragging`を分け、ドラッグ中は主に終点だけを更新します。押下時の選択オプションは開始後に保持していません。

同ファイルはドラッグ閾値、自動スクロール、PRIMARYへのコピー、Ctrlクリック、フォーカス喪失、切断なども扱います。[terminal-selection-state-test.cpp](../../../elder-terms-terminal/tests/cpp/terminal-selection-state-test.cpp)、[terminal-selection.test.ts](../../../elder-terms-terminal/tests/terminal-selection.test.ts)、[terminal-selection-scroll.test.ts](../../../elder-terms-terminal/tests/terminal-selection-scroll.test.ts)が既存の検証対象です。

## 状態変化の規則

| 入力 | 期待する動作 |
| --- | --- |
| Ctrlなしで左ボタンを押してドラッグを開始 | 初期モードを通常選択にする |
| Ctrlありで左ボタンを押してドラッグを開始 | 初期モードをブロック選択にする。追加のCtrl操作は不要 |
| 通常選択中にCtrlを押す | まだ変えない |
| Ctrlを押したまま座標が変わるmotionを受ける | 同じ開始点からブロック選択へ切り替える |
| ブロック選択中にCtrlを離す | まだ変えない |
| Ctrlを離した状態で座標が変わるmotionを受ける | 同じ開始点から通常選択へ切り替える |
| 同じ座標のmotion、修飾キーだけの通知 | 切り替えない |
| マウスホイール、自動スクロール、再描画 | 終点の更新は既存の規則に従うが、モードを切り替える契機にしない |
| Ctrlを切り替えた後、動かさず左ボタンを離す | 直前に適用していたモードで確定する |
| 動かさずCtrlを押して離し、その後移動する | 最後のCtrl状態を使う。適用済みのモードと同じなら切替は不要 |
| 同じセル内でポインターが移動する | 座標が変わっていれば切替条件を満たす。別セルへの移動は要求しない |
| ドラッグ閾値に達する前にCtrlが変わる | 初期値は押下時のmodifierのまま保持する。選択開始後、実移動とCtrl変化の条件を満たしたmotionで切り替える |

押下時のmodifierから初期オプションを作り、既存の`pending`状態を経てそのオプションで選択を開始します。開始を確定したイベントがmotionで、開始点からの実移動とCtrl変化の両方がある場合は、そのイベントで続けて切替を適用します。これは押下時の初期値を置き換える処理とは分けて検証します。

ポインターの前回座標は、スクロール後のヒット結果とは分けて保持します。文字がスクロールして同じ座標の下へ別のセルが来たことを、マウス移動と見なしません。開始後の判定はキーイベントで保存するCtrl状態だけに頼らず、実際のmotionに付いた修飾キーを使います。

通常選択へ戻すときの選択単位は、最初のドラッグに従います。単クリックなら文字、ダブルクリックなら単語、トリプルクリックなら行です。ブロック選択中はboxrigが対応する文字単位にし、通常へ戻したときに元の単位へ戻す方針です。開始時からCtrlが押されていたドラッグの通常復帰先は文字単位にします。

## 開始点を保つ方法と外部依存

開始点は押下時のウインドウ座標だけで保持できません。論理行ID、revision、文字境界、折り返し断片、表示列など、現在の選択が使う情報を保持します。自動スクロールで開始点が画面外になっても、同じ文字から切り替えられることが条件です。

[boxrigのテキスト文書](../../../deps/boxrig/docs/ja/text.md)と[公開ヘッダー](../../../deps/boxrig/include/boxrig/ui/view.h)を確認しました。現状の`begin_selection_with_options()`はアクティブな表示領域のヒット結果で開始し、`update_selection()`は終点を更新するAPIです。開始点を保ったまま形状だけを変更する関数は、確認した公開範囲にはありません。

画面内の開始点では、同じ論理位置を指す新しいヒット結果を得て選択を再開できる可能性があります。画面外の開始点へ古いヒット結果を渡したり、座標を捏造したりする方法は公開契約を満たしません。段階1で、現在のAPIの組合せで全条件を満たせるかを試験します。

不足する場合に必要な公開契約は、現在の開始点と終点を保持した形状・単位の変更、表示領域外の開始点、失敗時の以前の選択の保持です。boxrigのソースやサブモジュール参照は本作業で変更しません。必要なAPIが別途提供・取り込みされるまでは製品への統合を依存待ちとし、画面内だけの動作で本planを完了扱いにしない方針です。

## 既存操作との整合

Ctrlクリックによるリンク起動は、ドラッグへ移行しなかった場合だけ成立させます。モード切替のたびにクリックとして再解釈したり、マウス報告モードの端末へ同じイベントを送ったりしません。一度アプリ側の選択として開始したジェスチャーは、Ctrlを離しても途中で端末へ渡しません。

切替直前に論理位置とレイアウトを検証します。リサイズ、再接続、選択テキストの消失、フォーカス喪失、別ボタンの押下などで無効になった操作は、既存と同じく中止します。古い開始点を別の文字へ付け替えません。

PRIMARYとCLIPBOARDへ出す文字列は、最後に適用したモードを使います。ブロックコピーの行末空白設定、幅広文字、結合文字、双方向文字、折り返しの扱いは既存のboxrig契約を維持します。モード切替の表示更新だけでクリップボードを上書きしません。

## 段階1：条件を再現し、公開APIを検証する

固定した複数行の端末出力を使い、押下時のCtrlなし・ありによる初期モードと、ドラッグ中の往復切替を別々に検証します。初期モードの既存テストを維持し、新しい「Ctrlだけでは変わらない」「次の実移動で変わる」をRED確認します。押下後から閾値成立までにCtrlが変わるケースと、開始点が画面外になるケースも同じドライバーで試します。

成果物は実行可能な再現ドライバー、API適合の結果、必要なら不足する契約の記録です。完了条件は、以後の実装に使う公開APIが全条件を満たすと確認できることです。不足する場合は前節の依存条件を満たしてから段階2へ進みます。

## 段階2：実移動時のモード切替を実装する

元の開始点・選択単位、押下時のCtrlによる初期モード、適用中のモード、直前の実ポインター座標を保持します。開始後にCtrl状態を再評価する契機は、座標が変わるmotionです。必要な場合だけ形状を変更し、終点更新と一つの描画更新として扱います。空の選択が途中で見えないことも条件です。

完了条件は、通常からブロック、ブロックから通常を繰り返せて、同じ開始点と正しいコピー内容を保つことです。キーだけの入力、同一座標、左ボタン解放では形状が変わりません。

## 段階3：スクロールとリンク操作を統合する

開始点が上下の画面外にある場合、ホイール、自動スクロール、折り返し、右から左へのドラッグを検証します。ダブル・トリプルクリック、Ctrlクリック、マウス報告モード、IME、選択中の出力更新も既存動作と照合します。

入力列と動画を対応付け、Ctrlを押した時点では形状が変わらず、移動後のフレームで変わることをアサートします。最終画像だけの比較では合格にしません。完了条件は、時間軸を含めて要求どおりに切り替わり、リンク起動や端末への誤入力が起きないことです。

## 段階4：全体検証と利用者向け説明

既存の選択、空白除去、スクロール、リンク、入力遅延の試験を実行します。画像・動画を目視確認し、`make test`で全体を検証します。操作説明には「Ctrlの変化を次のマウス移動で反映する」と記載します。

## 最終完了条件

1. 左ボタン押下時のCtrl modifierで、現在と同じ通常・ブロックの初期モードを選ぶ。その後、同じドラッグ中に双方向へ切り替えられる。
2. Ctrlだけでは変わらず、その後の座標が変わるmotionで現在の状態を反映する。
3. 画面外の開始点、スクロール、折り返しでも同じ開始点を保ち、正しい文字列をコピーする。
4. Ctrlクリック、マウス報告、フォーカス喪失、再接続の既存操作を損なわない。
5. 公開APIだけを使用し、動画・目視確認・全体テストが完了している。

### 再現ドライバー

[terminal-selection-state-test.cpp](../../../elder-terms-terminal/tests/cpp/terminal-selection-state-test.cpp)へ、引数で選べる試験を追加しました。既存の端末ランタイムへGTKの入力イベントを送り、選択形状、開始点、コピー文字列、PRIMARYとCLIPBOARDを確認します。固定の3行と、番号付きの100行の履歴を使用します。

| 引数 | 検証内容 | Cairo/OpenGL・表示倍率1/2での結果 |
| --- | --- | --- |
| `mode-baseline` | 押下時のCtrlによる初期モード。Ctrlだけ、同一座標のmotion、ボタン解放では形状を変更しない | 4件成功。各件で通常・ブロックの両方を確認 |
| `mode-roundtrip-linear` / `mode-roundtrip-rectangular` | 選択開始後にCtrlを変更し、同じセル内の実移動で切り替えてから元へ戻す | 8件RED。最初の実移動でも形状が変わらない |
| `mode-pending-linear` / `mode-pending-rectangular` | 閾値未満でCtrlを変更し、選択を開始するmotionで切り替える | 8件RED。押下時の形状のままになる |
| `mode-history-linear` / `mode-history-rectangular` | 開始点が画面下へ外れるまでホイールでスクロールし、同一座標では保持、次の実移動で切り替える | 8件RED。ホイールと同一座標では保持されるが、実移動でも形状が変わらない |
| `mode-api` | 画面内での選択の作り直しと、画面外になった古い開始ヒットの受理・拒否を観測する | 4件実行。詳細は次節 |

往復試験は最初の切替で失敗するため、復帰側の検証には到達していません。通常始まりとブロック始まりを別々に実行し、両方向の未実装を確認しました。REDを再現する引数は明示実行用として残し、通常の全体テストには`mode-baseline`だけを追加しています。全体テストの成功を、切替機能の成功とは扱いません。

### 公開APIの適合結果

採用版の[公式テキスト文書](https://github.com/kekyo/boxrig/blob/46483d91f47f392ca580493326074e36b37df3d0/docs/ja/text.md)と、[公開ヘッダーの選択APIコメント](https://github.com/kekyo/boxrig/blob/46483d91f47f392ca580493326074e36b37df3d0/include/boxrig/ui/view.h#L1696-L1769)をローカルのサブモジュールで照合しました。`begin_selection_with_options()`は現在の表示領域で得たヒット結果から選択を開始し、`update_selection()`は既存の形状で終点を更新します。保持中の開始点・終点を使って形状と単位だけを変更する公開関数はありません。

| 試した組合せ | 観測結果 | 採用判断 |
| --- | --- | --- |
| 画面内の開始点を再ヒットし、新しい形状で開始して終点を更新 | 通常・ブロックの両方向で期待する文字列を取得 | 画面内での作り直しは可能。画面外の条件を満たさない |
| 通常選択の開始点を画面外へ移動し、保存した古いヒットでブロック選択を開始 | `BOXRIG_UI_STALE`。以前の形状・開始点・終点・本文は保持 | 画面外の開始点からブロック選択を再開できない |
| ブロック選択の開始点を画面外へ移動し、保存した古いヒットで通常選択を開始 | この版では`BOXRIG_UI_OK` | ヒットの条件が公開契約外のため、製品の実装には使用しない |

`mode-api`は公開契約外の入力も観測する調査用ドライバーです。古いヒットが受理されることを保証する回帰テストにはしていません。画面外に開始点があることは、表示中の各行から得た新しいヒットの論理行IDが開始点と一致しないことでも確認しています。

段階2へ進むには、boxrigで次の契約を公開し、別途取り込む必要があります。

- 保持中の開始点と終点を使って、通常・ブロックの形状と選択単位を変更できる。
- 開始点が表示領域外でも、論理行ID、revision、文字境界、折り返し断片、表示列を保持する。元の単語・行単位へ戻すための開始位置も失わない。
- 無効な位置、レイアウト変更、上限超過、メモリ不足で失敗した場合は、以前の形状・範囲・コピー内容を保つ。
- 変更を一つの描画更新へまとめられ、途中の空選択を表示しない。

画面内だけの切替は製品へ追加していません。段階2の実装、段階3の統合・切替動画、段階4の新操作の利用者向け説明は未着手です。最終完了条件1～3は未達で、条件4～5の切替機能を含む検証も依存解消後に実施します。
