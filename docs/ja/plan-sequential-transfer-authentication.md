# ファイル転送の認証入力を2段階にする

## 対象と完了条件

FTP/FTPSと、同じ2欄のオーバーレイを使用するWebDAV Basic/Digest認証を対象にする。SSH/SFTPと同様、ユーザー名を確定してから別のオーバーレイでパスワードを入力する。接続前のユーザー名初期値、匿名FTPの案内、空・空白のみのユーザー名の再入力、パスワード非表示、キャンセル時の接続中止、再接続時の入力、証明書確認とその後の接続を維持する。認証不要なWebDAVは入力を表示しない。

完了条件は、各プロトコルの画面と実サービスで順序どおり入力でき、既存の操作と全体テストが成功すること。利用者向けの説明も現在の挙動に一致させる。使われなくなった2欄入力専用の要素は整理する。

## 実装手順

1. FTP/FTPSの画面・実サービスのテストで、ユーザー名の確定後にパスワード欄だけを表示する期待を追加する。全体テストでREDを確認し、FTP/FTPSフローを実装してGREENを確認しコミットする。
2. WebDAVのBasic/Digestおよび証明書確認のテストを同様に変更し、全体テストでREDを確認する。WebDAVフローを実装し、利用者向けWebDAV文書を更新する。全体テストでGREENを確認しコミットする。
3. 2欄同時入力の支援コードが未使用になった場合は、旧動作を確認するテストをREDにしてから機能を削除しGREENを確認する。その後、削除確認だけを目的とするテストを取り除き、全体テストを通してコミットする。

## APIの確認

オーバーレイには既存の `prompt_file_transfer_window_async` と `InlinePromptRequest` を使用する。これらの公開ヘッダーのAPIコメントと、依存するcardioの公開ヘッダー・[公式資料](https://github.com/kekyo/cardio)を確認する。GTKの既存ラベル・エントリAPIを利用する。

## ステップ1のRED

変更前のネイティブ全体テストは128件成功、2件スキップ。FTP/FTPSの実サービスを含む全体GUIテストで、ユーザー名の確定後にパスワード入力画面へ進まないため接続エラーになることを確認した。旧動作との差を示す失敗を得た後、FTP/FTPS側の入力を2段階に変更した。

## ステップ1のGREEN

- ネイティブ全体テストは128件成功、2件スキップ。GUI全体テストは21ファイル441件すべて成功した。
- FTP/FTPS実サービス、匿名ユーザー名、初期ユーザー名、空のユーザー名の再入力、日本語表示、証明書確認、再接続、ファイル操作の各経路で2段階の入力が成功した。
- 利用者向けREADMEのFTP認証手順を更新し、ステップ1の完了条件を満たした。
