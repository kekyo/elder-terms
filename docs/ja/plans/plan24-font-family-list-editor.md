# plan24：フォントファミリーリストの編集UI改善

作成日：2026年11月2日

状態：計画作成。実装は未着手です。4案を比較し、案Aを推奨します。採用案はまだ確定していません。

## 目的

端末で使うフォントを探し、追加し、優先順を変える操作を分かりやすくします。フォントファミリーリストは、文字を描く際に試すフォント名を優先順に並べた設定です。先のフォントにない文字を後の候補で補うため、名前だけでなく順序も編集対象になります。

設定の保存形式は既存の`[terminal] font_families`を使い、フォントサイズや字形の選択とは分けます。対象は編集UIと、その下書き・継承状態の扱いです。フォントの導入や配布、端末のフォント選択アルゴリズムの変更は含めません。

調査基準は`48a002ac`です。[plan15](plan15-transfer-jobs-and-tree-icons.md)の共通条件に従い、段階ごとに操作できる成果物を作ります。[plan23](plan23-named-settings-themes.md)との統合では、テーマ内の編集と接続側の継承にも同じUIを使います。

## 現在のUIとコード

[現在のフォント編集画面](../../../images/font-family-settings.png)を確認しました。各行に名前の入力欄と、選択、上へ、下へ、削除の4ボタンが並びます。上部には継承モードと追加ボタンがあり、候補が増えるほど同じ操作ボタンが縦に続く構成です。

| 領域 | 現状 |
| --- | --- |
| 行の編集と並べ替え | [settings-widget.cpp](../../../shared/src/settings-widget/settings-widget.cpp)の`rebuild_terminal_font_rows()`と関連処理が担当する。並べ替え・削除では行を作り直し、行番号に結び付いた選択ダイアログを閉じる |
| フォントの追加 | 空の行を末尾へ追加し、そこへフォーカスする。名前の入力か、その行の選択ボタンによる指定が必要 |
| フォント候補の選択 | `GtkFontChooserDialog`をファミリー単位で開く。結果からファミリー名だけを取り出す |
| 入力検証 | [terminal-settings.cpp](../../../shared/src/settings/terminal-settings.cpp)が空名、重複、カンマ、制御文字、不正なUTF-8を拒否する。候補名の前後の空白は正規化する |
| 継承と既定値 | 同ファイルの`terminal_font_families()`は、空の設定値を現在のアプリ既定候補`Noto Sans Mono`、`Monospace`へ解決する。未指定と明示的な空リストは、設定の出自が異なる |
| 端末への適用 | [terminal-presentation.cpp](../../../elder-terms-terminal/src/terminal-presentation.cpp)が順序付きの候補を既存のboxrig公開APIへ渡す。変更がない場合は再適用を避ける |
| 既存のUI検証 | [settings-widget.test.ts](../../../shared/tests/settings-widget.test.ts)が追加、並べ替え、削除、12件以上の一覧、継承値の更新、不正な下書き、キャンセルを検証する |
| 実際の描画 | [font-fallback.test.ts](../../../elder-terms-terminal/tests/font-fallback.test.ts)が後方候補の文字の描画、未導入候補、実行中の順序変更を検証する |

改善の着眼点は、ボタンの反復で名前の表示幅が減ること、離れた位置への移動に何度も操作が必要なこと、追加と候補選択が別操作になっていることです。行の再構築がフォーカスやスクロールに与える影響は、既存試験に加えて実操作で確認します。現在のコードだけから、未確認の表示不具合があるとは断定しません。

## UIの比較案

| 案 | 操作方法 | 利点 | 比較する点 |
| --- | --- | --- | --- |
| A・推奨 | 優先順の一覧で一行を選び、共通の追加・変更・削除・上下移動を使う。行のドラッグでも順序を変える | フォント名の表示幅を確保でき、操作位置が固定される。現在の設定画面へ収めやすい | 行の選択と名前編集の区別、ドラッグ中の挿入位置、長い一覧のスクロール |
| B | 専用の編集ダイアログで、左に検索可能な候補、右に使用順の一覧を置く | 複数のフォントを比較・追加しやすく、候補と使用中の名前を同時に見られる | 広い画面が必要。設定画面とダイアログで確定・キャンセルを区別する必要がある |
| C | フォント名を横並びのタグとして表示し、検索入力から追加する。タグのドラッグで順序を変える | 2～3件なら省スペースで、直接編集しやすい | 長い名前や多数の候補では折り返す。優先順とキーボード移動を分かりやすく示す必要がある |
| D | 一行に一つの名前を書く複数行テキスト欄を使う。行単位の移動と候補挿入を補助する | 他の接続からのコピーや、多数の候補の一括編集に向く | 候補の発見と単体の見本表示が弱い。不正な名前や重複を行ごとに示す必要がある |

Aは、現在の縦の優先順を保ちながら、各行に繰り返す操作を一か所へ集める案です。Bは、フォントを探しながら何件も比較する操作に向きます。Cは候補数が少ない場合、Dは既に名前を把握している場合に適しています。Dを補助的な「一括編集」としてAやBに併設する案もありますが、最初からすべての編集方式を製品へ追加する方針にはしません。

### A案：優先順の一覧と共通操作

設定ページ内に、優先順、フォント名、候補の検出状態を並べます。上部の操作は選択行へ作用し、ダブルクリックまたは「変更」で名前の編集・候補の選択を行う構成です。「追加」は検索入力と候補一覧を開き、選んだ名前を追加します。空の行を作ってから別の選択ボタンを押す手順を減らします。

配置の初期案は次のとおりです。文字列や行数は比較用で、固定の製品仕様ではありません。

```text
フォントの指定  [この接続で指定する ▼]
上のフォントから順に、描けない文字を後の候補で補います。

[追加] [変更] [削除]                 [上へ] [下へ]
優先順  フォント名
  1     DejaVu Sans Mono
  2     Noto Sans Mono CJK JP    ← 選択行
  3     Monospace

選択したフォントの見本:  ABC 0123 日本語 ┌─┐
```

一覧は高さに上限を設け、候補数が増えても設定ウインドウ全体を縦に広げません。追加した行、移動した行、削除後の隣接行へ選択とフォーカスを保ち、必要な範囲だけスクロールします。ドラッグの挿入位置は線で示し、ドロップ前には保存値を確定しない方針です。

### B案：検索候補と使用順を左右に表示

設定ページには現在の候補の要約と「編集」を置きます。編集ダイアログの左側でフォントを検索し、右側へ追加して順序を決める構成です。複数候補を追加する場合は、追加後の順序を事前に確認できるようにします。右側の並べ替え操作はA案と同様です。

ダイアログの確定は親の設定画面の下書きへ反映し、親画面の保存・適用で初めて永続化・実行中の端末へ反映します。ダイアログのキャンセルでは、開く前のリストをそのまま残します。

### C案：検索入力付きのタグ列

各フォント名を削除操作付きのタグとして並べ、末尾の検索入力で候補を追加します。優先順はタグにも表示し、折り返した後も読む順序が分かる構成です。キーボードでもタグを選び、左右移動・削除・名前の変更ができることが条件です。

長い日本語名、12件以上の候補、狭い設定画面で比較します。省スペースという利点が失われる場合は、単に見た目が軽いことを理由に採用しません。

### D案：一行一候補のテキスト編集

改行で候補を分け、各行を一つのファミリー名として扱います。空白を含む名前を単語に分割せず、順序も入力どおりです。候補の挿入操作はカーソルの行へ一件を入れる形にします。

入力エラーは該当行へ示し、問題のある一行のために編集内容全体を消しません。もしAやBの補助として採用するなら、テキスト欄と一覧を往復しても順序・名前が変わらないことを条件にします。

## 全案に共通する操作と表示

### 候補の検索と追加

名前で絞り込み、候補を選んで追加できるようにします。候補一覧を名前順にしても、使用順の一覧を勝手に並べ替えません。検索中の入力や候補の閲覧だけでは、設定を変更済みにしないことが条件です。

候補一覧にない名前も、現在と同じく手入力・保存を可能にします。別環境用の設定や汎用名を扱うため、列挙結果にないことだけで不正な名前と判定しません。名前の検証と重複判定は既存の規則に従い、大文字・小文字を独自に統一して別の名前へ変換する処理は加えません。

等幅フォントへ絞る表示は補助操作として比較し、常に全候補へ戻せるようにします。後方候補として使うフォントまで、等幅という判定だけで選択不可にしません。

### 継承と既定値

継承、アプリ既定の明示使用、個別指定を区別します。plan23との統合後は、継承元がテーマならその名前を表示します。リストは一つの設定値として扱い、グローバルとテーマの候補を勝手に連結しません。

| 操作 | 保持する設定の意味 |
| --- | --- |
| 継承を選ぶ | この層の明示値を解除し、テーマまたはグローバル既定値を使う |
| アプリ既定を使う | 明示的な空リストで、上位のフォント指定を上書きする。グローバル編集では現在の組み込み既定への復帰に相当する |
| 個別指定を始める | 現在の実効リストを編集の出発点にし、明示したリストとして扱う |
| 個別指定の最後の候補を削除する | アプリ既定へ戻ることを表示する。テーマや接続では、継承解除と明示的な空リストを混同しない |
| 継承元が変更される | 継承中の表示を更新し、個別指定の値・未保存入力・選択中の項目を保つ |

継承中のリストと編集可能なリストは、継承元の表示と操作の状態で区別します。ダイアログを開く、検索する、行を選ぶだけで明示指定へ変えません。名前や順序を編集する際には、現在の層で指定する操作だと分かる入口を用意します。

### キーボードとフォーカス

全案で、追加、名前変更、上下移動、削除、確定、キャンセルまでをキーボードで操作できることが条件です。移動は選択行用のボタンとキー操作を用意し、操作後も同じ候補が選ばれている状態を保ちます。削除キーは名前入力中の文字削除と競合させません。

選択ダイアログの終了、継承値の更新、行の並べ替えが重なっても、古い行番号で別の候補を書き換えないようにします。入力エラーは該当する候補へ表示し、修正する位置を追えることが必要です。

### フォントの見本

候補を選ぶ際には、英数字、日本語、罫線を含む短い見本を表示する案です。これは選択した候補の見た目を比較する表示で、端末全体のフォント優先順を正確に再現したものとは扱いません。GTK側の見本でも文字の補完が起こり得るため、すべての文字を選択候補自身が持つという表示はしません。

優先順の正しさは既存の端末へ適用して確認します。リストを眺めているだけで実行中の端末へ繰り返し適用せず、適用・キャンセルの現在の境界を維持します。

## 実装範囲と公開API

編集部分を、順序付きの名前リスト、入力検証、選択状態を扱う小さなUI部品へ分ける案です。既存の`SettingsStore`と設定画面への接続は残し、リスト編集のための汎用フレームワークは作りません。候補の一覧取得や検索を行の描画ごとに繰り返さず、編集画面内で必要な情報を再利用します。

候補の取得には[Pangoのファミリー列挙API](https://docs.gtk.org/Pango/method.FontMap.list_families.html)、等幅の表示には[ファミリーの等幅判定](https://docs.gtk.org/Pango/method.FontFamily.is_monospace.html)を候補とします。現在の選択ダイアログは[GTK3のFontChooser](https://docs.gtk.org/gtk3/iface.FontChooser.html)を使用しています。採用する方式に合わせ、利用中の版の公式文書と公開APIコメントを再確認します。

boxrigのAPI追加やソース変更は想定しません。既存の順序付きファミリー指定を使用し、保存・適用のデータ契約を維持します。使わなくなる行別ボタン、再構築処理、ダイアログ管理は、代替UIが動く段階で整理する方針です。

## 段階1：操作できる比較画面を作る

既存の[settings-widget-fixture.cpp](../../../shared/tests/settings-widget-fixture.cpp)を基に、A・Bの比較用画面を作ります。C・Dは配置と操作列も比較し、採用候補になった場合に実操作まで検証します。比較に必要な部分から実装し、全案を完成させてから選ぶ手順にはしません。

同じ候補で、検索して追加、末尾から先頭へ移動、削除、キャンセル、継承への復帰を試します。候補数3件と12件以上、長い名前、狭い画面、キーボード操作を揃えて比較する方針です。

成果物は比較画面、画面・操作動画、操作回数とフォーカス移動を記録した結果です。操作結果を検証するテストは、比較用UIの追加前にRED、追加後にGREENを確認します。完了条件は、採用案、配置、追加位置、キー操作、既定値へ戻す表示を決めることです。選んだ操作を、次の段階の製品テストへ反映します。

## 段階2：選んだUIで編集・保存を完成させる

採用案で追加、変更、上下移動、削除を実装し、実際の設定の保存・再読み込みへ接続します。最初の成果物は、キーボードとボタンで操作できる画面です。ドラッグの実装前にも優先順の変更を観測できます。

未導入候補、重複、空の入力、前後の空白を検証します。成果物は既存端末へ適用できる編集画面です。完了条件は、表示した順序が保存値と実際の描画へ反映され、キャンセルで未適用の変更を戻せることです。

## 段階3：検索・移動・継承を統合する

候補検索、採用案の見本表示、ドラッグを使う案ならその移動操作を完成させます。大量候補の表示、追加位置へのスクロール、削除後の選択、キー操作、ダイアログを閉じる際のフォーカスを検証します。アニメーションやドラッグの途中状態は、動画で操作列と対応付けてアサートします。

plan23のテーマ編集と接続の継承元表示へ統合します。plan23が未実装の場合は既存のグローバル・接続設定で動作を確認し、テーマとの統合を残件として扱います。完了条件は、同じ編集部品が各設定の層で正しく動き、下書きの更新や継承元の変更で操作対象を失わないことです。

## 段階4：回帰確認と旧UIの整理

既存の追加・並べ替え・長い一覧・保存・不正入力保持のテストを、採用した操作へ更新します。検証対象は、操作後の優先順、保存値、フォーカス、描画結果です。

`font-fallback.test.ts`で、後方候補による文字の補完と実行中の適用を確認します。不要な旧UIの削除は共通条件に従ってRED・GREEN確認とコミットを行い、削除確認だけの一時テストはその後に撤去します。

日本語・英語、明色・暗色、表示倍率、狭い画面で見た目を目視確認します。画像・動画の確認を終え、`make build`と`make test`で全体を検証します。利用者向けの説明と画像も、新しい編集方法へ更新します。

## 最終完了条件

1. 比較結果から採用案を決め、フォントの追加、変更、削除、優先順の変更を実画面で操作できる。
2. 12件以上や長い名前でも、選択・フォーカス・スクロール位置を追え、キーボードだけで編集できる。
3. 未指定、明示的なアプリ既定、個別指定を区別し、plan23のテーマと接続設定で継承・上書き・解除が働く。
4. 候補一覧にない名前を保持し、不正な入力は対象位置へ示す。検索や見本表示だけでは設定を変更しない。
5. 表示順、保存順、端末への適用順が一致し、後方候補による文字の補完を維持する。
6. 不要な旧UIを整理し、boxrigを変更せずに、画像・動画・全体テストと利用者向け説明を完了している。
