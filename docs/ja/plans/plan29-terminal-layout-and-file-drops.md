# plan29 接続ウインドウの操作、端末の余白とファイルドロップ

2026年11月23日作成。elder-termsの基準は1.14.0の`254bddc8`です。タイトルバーの操作、通信インジケーター、テキスト送信速度、端末とファイル転送ウインドウへのドラッグアンドドロップを扱います。端末セルの余白にはboxrigの新しい配置機能を使います。

boxrigの調査には、同日にリモートと照合した`origin/develop`の`0fb7d5f`を使いました。elder-termsが現在固定している`deps/boxrig`は0.15.0の`ee66910`です。上流の計画はboxrigリポジトリの`docs/ja/plans/plan30-text-defaults-and-grid-placement.md`にあります。29.1〜29.6は現在の依存で実装でき、29.7でplan30の検証済みコミットを取り込みます。[boxrigの調査基準](https://github.com/kekyo/boxrig/commit/0fb7d5fcccd7490b390e55e2c6ac1a604683c1d4)・[現在の依存を取り込んだ経緯](plan28-boxrig-015-followup.md)

## 29.1 タイトルバーの縁でウインドウをリサイズする

1.14.0で端末とファイル転送ウインドウを開き、左ボタンで実際にドラッグして外形の変化を測りました。環境はX11、KWin、Adwaita、表示倍率1倍、ボーダー表示あり、幅8 pxです。通常表示とコンパクト表示で次の傾向を確認しました。

| ドラッグを始めた位置 | 観測した動作 |
| --- | --- |
| 本文の左ボーダーの端から4 px内側 | 横幅が変わった |
| タイトルバーの左端または右端から4 px内側 | ウインドウが移動した |
| タイトルバーの上端から1 px内側 | ウインドウが移動した |
| タイトルバーの上端から4 px外側 | 高さが変わった |

共通のリサイズ処理が受け取るのは本文の左右とコンパクト表示の下辺です。上辺はGTKのウインドウ装飾で処理しています。既存試験にタイトルバーの左右・上辺・上の二隅を加え、現行版で再現します。ボーダー表示時のリサイズ範囲は、左右では本文から上端まで続く帯、上辺ではタイトルバーの内側にある同じ幅の帯です。カーソルとドラッグ開始には同じ位置判定を使います。[共通のリサイズ処理](../../../shared/src/connection-runtime/window-resize-border.cpp)・[既存のボーダー試験](../../../shared/tests/window-border-resize.test.ts)

完了条件は、両ウインドウで左右・上辺をつかんで各方向にリサイズでき、上の二隅では幅と高さの両方が変わることです。中央をドラッグするとウインドウが移動し、操作ボタンを押せばそのボタンが働きます。ボーダーの外側にある影からはリサイズを開始しません。ボーダー非表示時のGTK標準操作と、最大化・タイル時に操作できる辺も照合します。試験環境はX11とWaylandで、通常・コンパクト表示と表示倍率1倍・2倍が対象です。

## 29.2 テキスト送信の既定速度を倍にする

`[transfer] text_send_bytes_per_second`の既定値を1,024 B/sから2,048 B/sに変更します。単位は文字コード変換後の送信バイト数です。テキストファイルとクリップボードからのペーストは同じ送信設定を使います。設定定義、設定欄を空にしたときの値、送信要求と試験用ドライバーの初期値を揃えます。[設定定義](../../../shared/src/settings/transfer-settings.cpp)・[設定欄を空にしたときの処理](../../../shared/src/settings-widget/settings-widget.cpp#L2130-L2142)・[送信要求](../../../elder-terms-terminal/src/terminal-text-send.h#L116-L117)・[ドライバーの初期値](../../../elder-terms-terminal/src/boxrig-driver.cpp#L43)

未指定時の速度と、設定欄を空に戻したときの表示を試験に加えます。完了条件は、新規設定で2,048 B/sになり、明示した1,024 B/sなどの値と継承元の値がそれぞれ有効になることです。既存の試験用時計を使って送信量と送信間隔を照合し、ファイルとペーストのどちらも改行設定に沿って相手に届くことを確認します。[送信速度の試験](../../../elder-terms-terminal/tests/cpp/terminal-text-send-runner-test.cpp)

## 29.3 通信インジケーターの表示を切り替える

設定案は`[general] show_indicators=true`です。「一般」の点灯色・消灯色の近くに表示設定を置きます。既定は表示です。端末とファイル転送ウインドウのランプ全体に適用し、シリアル接続時の信号線も一緒に切り替えます。対象はランプの表示だけです。ステータスの文言、回線の監視、ログ記録、タイトルバーの受信効果はそれぞれの設定に従います。

ランプの表示先は、通常表示ではステータスバー、コンパクト表示ではタイトルバーです。両方のウインドウに表示先を移したランプを再表示する処理があるため、OFFのまま往復する試験を先に追加します。[端末の表示切り替え](../../../elder-terms-terminal/src/main-window.cpp#L1594-L1621)・[ファイル転送の表示切り替え](../../../elder-terms-file-transfer/src/file-transfer/file-transfer-window.cpp#L2910-L2936)

完了条件は、OFFにするとランプが占めていた幅が詰まり、ONに戻すとその時点の接続・ログ・信号線の状態が見えることです。実行中の適用、設定の保存・再起動、グローバル設定とテーマからの継承、接続側の上書きと解除を確認します。SSH端末から開いたSFTPウインドウも対象です。

## 29.4 端末に落としたファイルの送信方法を選ぶ

GTK3の端末領域でファイルの場所を示すURIの一覧を受け取り、ドロップした位置に送信メニューを開きます。利用者が方式を選ぶと、既存のファイル選択後と同じ送信処理にURIを渡します。ファイル名に空白や日本語があっても、対象はそのファイルの内容です。[GTK3のURI受け取り](https://docs.gtk.org/gtk3/method.Widget.drag_dest_add_uri_targets.html)・[既存のファイル選択と転送開始](../../../elder-terms-terminal/src/main.cpp#L1234-L1264)・[接続方式ごとの送信メニュー](../../../elder-terms-terminal/src/main.cpp#L1742-L1786)

| 接続とドロップ内容 | 選択できる送信方法 |
| --- | --- |
| ローカルシェル・1ファイル | テキスト送信 |
| シリアル・SSH・Telnetのいずれか・1ファイル | テキスト、XMODEM、XMODEM 1K、YMODEM、ZMODEM |
| シリアル・SSH・Telnetのいずれか・複数ファイル | YMODEM、ZMODEM |

テキスト送信だけが候補の場合も、確定するまで入力を送りません。ローカルシェルへの複数ファイルやディレクトリなど、送信方法がない組み合わせでは理由を表示します。メニュー表示中に切断や別の転送が起きた場合は、方式を選んだ時点の接続・転送状態が判断基準です。端末内の文字選択とリンクのドラッグは従来の操作に従います。

完了条件は、メニューを閉じた場合の送信量が0バイトで、確定した場合だけ受信側に期待した内容が届くことです。テキストでは速度・改行、XYZMODEMでは方式・ファイル数・内容を照合します。進捗とキャンセル、切断時の扱いは既存の送信メニューと揃えます。[テキスト送信の開始処理](../../../elder-terms-terminal/src/main.cpp#L1348-L1386)・[XYZMODEMの転送試験](../../../elder-terms-terminal/tests/xyzmodem-transfer.test.ts)

## 29.5 ファイル転送ウインドウの左右のペインで送受信する

ペインは、同じウインドウにあるローカル側とリモート側のファイル一覧です。ローカルからリモートへ落とすと送信、逆なら受信です。外部のファイルマネージャーからリモートペインへ落としたローカルファイルも送信できます。どの方向も操作はコピーです。

保存先はドロップ位置から決めます。フォルダーの行ならその中、通常ファイルの行ならその親、一覧の空白なら現在表示中のフォルダーです。リモート項目の操作には、表示名とは別にクライアントが返すパスを使います。送受信とも既存のジョブキューに登録し、複数項目、フォルダーの再帰転送、進捗、同名の競合、キャンセルを既存メニューと揃えます。[既存の保存先判定](../../../elder-terms-file-transfer/src/file-transfer/file-transfer-window.cpp#L661-L679)・[ジョブの投入](../../../elder-terms-file-transfer/src/file-transfer/file-transfer-window.cpp#L2181-L2189)

完了条件は、ドロップした行と空白のそれぞれで転送先のファイル名と内容が一致し、元のファイルも残ることです。読み取り専用のHTTP接続や、SMB・NFSで項目を作成できない場所では、送信ジョブの登録件数が0になります。切断と再接続を挟んだときも、以前の接続の項目を次の接続に送らないことを確認します。[リモート側の操作可否と識別子](../../../elder-terms-file-transfer/src/file-transfer/remote-file-client.h)

## 29.6 リモート項目を外部ファイルマネージャーへ取り出す

外部へのドロップでは、相手が読めるファイルを渡すか、相手が示した保存先へ書き込む必要があります。候補は、X11の直接保存方式（XDS）と、一時領域に受信したファイルを渡す方式です。まず単一ファイルで試します。一時領域に受信したファイルは、ローカルURIか、アプリ間でファイルを受け渡すデスクトップポータルを通して渡せます。どちらの場合もリモートから読み出すのはelder-termsです。[X Direct Saveの仕様](https://www.freedesktop.org/specifications/direct-save/)・[File Transferポータルの仕様](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.FileTransfer.html)

X11とWaylandで実際のファイルマネージャーに落とし、使った相手と方式を記録します。比較するのは、複数ファイルの受け渡し、大きなファイルの受信中の進捗表示とキャンセル、相手が開くまでの一時ファイルの保持です。試した結果から方式を選び、既存の受信ジョブに接続します。

完了条件は、外部の保存先に期待する名前と内容のファイルが揃い、キャンセル・切断でも途中のファイルを成功として渡さないことです。一時領域を使う場合は、引き渡し後と中断後の両方で後始末を確認します。

## 29.7 boxrigの変更を取り込み、端末の余白を設定する

取り込み対象は、plan30で文字方向、絵文字表示指定子VS16の幅、セル領域の配置を検証したコミットです。`deps/boxrig`の参照を更新し、通常ビルドと配布用SDK（ヘッダーとライブラリ）の両方で端末を起動します。現在の明示指定と新しい既定値で、同じセル順（`LOGICAL`）とVS16の文字幅（`PRESERVE`）になることを既存試験で確認します。[文字幅とウィジェット再生成の試験](../../../elder-terms-terminal/tests/cpp/terminal-cell-width-test.cpp)・[SDKの準備](../../../scripts/prepare-boxrig.mts)

端末の設定画面に「パディング」と「セルの縦位置」を加えます。パディングは端末の四辺と文字セルの間に取る余白です。四辺共通の幅を表示倍率に依存しない論理ピクセル（DIP）で指定し、既定値は0とします。縦位置を既定の上寄せから下寄せに変えると、セルで割り切れない高さが上に、幅の端数が右に残ります。例えば表示倍率1倍、パディング4 px、縦の端数7 pxなら、上の余白は11 px、下は4 pxです。セル領域の外にスクロールバーを置き、パディングには端末の背景色や背景画像、透過を反映します。

配置はboxrigの公開APIに渡します。ズーム時にウインドウサイズを保つ`Keep window size`と、行数・桁数を保つ`Keep rows and columns`で使う設定は共通です。後者でも最大化やタイル配置で寸法が決まれば、余りは選んだ側に出ます。実行中の適用、継承・上書き・解除、設定を保存して再び開いた場合を確認します。[既存のズーム設定](../configuration.md)・[ズーム時の寸法調整](../../../elder-terms-terminal/src/terminal-runtime.cpp#L873-L911)

完了条件は、縦位置だけを変えてもウインドウ寸法と行数・桁数が同じで、先頭セル・末尾セルのクリックや選択が正しいことです。余白はセルとして反応せず、実際に行数・桁数が変わったときにはローカルの疑似端末（PTY）やSSH・Telnetの接続先にも同じ値が伝わります。CairoとOpenGLでリンク、入力メソッド（IME）の候補、背景、スクロールバーまで照合し、連続ズームと最大化・復帰中の表示を動画で確認します。[レイアウト試験](../../../elder-terms-terminal/tests/terminal-layout.test.ts)・[ズームと接続先の寸法の試験](../../../elder-terms-terminal/tests/boxrig-main-layout.test.ts)

## 計画全体の完了条件

各段階で期待する動作を試験にして、変更前の失敗（RED）と変更後の成功（GREEN）を確認します。コミットの単位は、操作できるアプリと対象試験が揃った段階ごとです。最後に利用者向けの設定・操作説明を更新し、`make build`と`make test`で全体を検証します。29.1〜29.7の完了条件を照合し、採用した外部ドロップ方式とboxrigの取り込みコミットを記録して完了とします。
