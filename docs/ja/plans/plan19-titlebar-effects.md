# plan19：BELとタイトル変更のタイトルバー演出

作成日：2026年11月2日

状態：計画作成。実装は未着手です。以下の時間・強度は比較用の初期案であり、実画面の動画を見て調整します。

## 目的

BELを受けたときのタイトルバー背景のフラッシュと、タイトル変更時のグラデーションを追加します。グラデーションは背景色を基準に横方向へ動かす方式です。文字やボタンを読める状態を保ちつつ、タイトル更新が起きていることを明確に伝えます。

二つの演出は同じ背景を使うため、このplanでまとめて設計します。表示の変化を端末の処理完了や転送の進捗と同じ意味にはしません。共通の実施条件は[plan15](plan15-transfer-jobs-and-tree-icons.md)に従います。

## BELのフラッシュ案

| 案 | 見え方と初期値 | 利点 | 調整が必要な点 |
| --- | --- | --- | --- |
| A・推奨 | 背景全体を基準色から明暗方向へ約15%変え、200～300msで滑らかに戻す | 現在の色を保ったまま気づきやすい。暗色・明色に合わせられる | 極端に明るい色や暗い色では変化量を補正する |
| B | 基準色にアクセント色を薄く重ね、300～400msで戻す | タイトル更新のグラデーションと区別しやすい | 接続色によって印象が変わるため色の選定が必要 |
| C | 短い明暗変化を2回行い、約400msで戻す | BELが連続しなくても通知を認識しやすい | A・Bより目立つ。連続BEL時に何回も点滅させない合流処理が必要 |

推奨A案で変化させるのは背景だけです。文字とボタン自身の不透明度は維持します。連続BELは新しいタイマーを積まず、現在の効果へ合流させる方針です。最初の立ち上がりを毎回やり直すと元へ戻れなくなるため、再点灯の間隔と終了条件を一つの状態で管理します。

標準音、独自音、音の再生失敗のいずれでも同じ視覚通知を発生させます。最小化中や非表示中は描画を走らせず、再表示後に古いBELを連続再生しません。通常の非アクティブウインドウでは、その状態の基準色に対して表示します。

## タイトル更新のグラデーション案

| 案 | 見え方と初期値 | 利点 | 調整が必要な点 |
| --- | --- | --- | --- |
| A・推奨 | 幅の約1/3の淡い明暗帯を左から右へ移動し、端で連続して循環させる。1周約1.2秒、色差8～12% | 動く方向がわかり、文字の邪魔になりにくい | 周回の継ぎ目と短いタイトルバーでの帯幅 |
| B | ヘッダー全体を緩い周期波のグラデーションにし、位相を横へ送る。1周約1.6秒、色差5～10% | 周回を自然につなげやすく、連続更新にも向く | 変化が弱すぎると動作を認識しにくい |
| C | 幅の狭い光沢帯を横へ通し、右端から左端へ回す一周期。約0.8秒 | 単発のタイトル変更を短く示せる | 更新が多いと光沢が目立ちやすい。ほかの案と同じ周期末の継続判定を使う |

すべて基準色から明度を少し上下させた色を作り、無関係な虹色にはしません。推奨A案は左右端が同じ状態になる循環関数で帯を作り、右端で消えて左端に急に現れる不連続を避けます。透明な帯だけを載せる方法と、基準色を含めて合成する方法を実画面で比較します。

演出の開始条件は、直前に表示した最終タイトル文字列との不一致です。初期表示や同じ文字列の再設定では始動しません。OSCによるタイトルだけでなく、切断表示など実際のタイトル文字列の変更も対象です。

## タイトル変化の記憶と周期の継続

タイトルの変化で最初の一周期を始め、その後の継続は周期の終了時だけに判断します。動作中の変化は真偽値で記憶し、変化回数に応じて周期を積み上げません。現在の周期の開始時刻や長さも変えない方針です。

| 状態・イベント | 処理 |
| --- | --- |
| 停止中にタイトルが変化 | 一周期を開始し、「周期中に変化した」という記憶をfalseにする。開始原因の変化だけで二周期にはしない |
| 動作中にタイトルが変化 | 記憶をtrueにする。位相と周期の終了時刻は維持する |
| 動作中に同じタイトルを再設定 | 記憶を変えない |
| 周期終了時に記憶がtrue | 記憶をfalseに戻し、次の一周期をシームレスに続ける。周期間の停止やフェードを挟まない |
| 周期終了時に記憶がfalse | 継続を終了し、基準背景へ戻る。最終停止の復帰にだけ短いフェードを使う案を比較する |

たとえば周期が1.2秒なら、0秒の変化で開始し、0.2秒にも変化があった場合は1.2秒で次周期へ進みます。その後に変化がなければ2.4秒で終了です。最後の変化からの経過時間で終了予定を延ばす方式にはしません。

同じ周期に`A → B → A`と変化した場合も、記憶はtrueのままです。周期末にタイトル文字列を比較するだけでは、途中の変化を失うためです。周期境界とタイトル更新は同じディスパッチャーで順に処理し、境界前の変化を消費した後に届いた変化は次周期へ記憶します。

インジケーターとは、活動を記憶して境界で消費する考え方を共通にします。ただし、グラデーションには点灯・消灯の区分がないため、一周期のどの時点でも変化を記憶する必要があります。既存のインジケーターの挙動は変更せず、タイトルバー用の小さな状態として実装する方針です。

## タイトル更新と演出の独立性

タイトル文字列は指示を受けた時点でGTKウインドウとタイトルラベルへ反映します。グラデーションの開始・終了・描画を待たず、周期内で複数回変わっても、そのつど最新の指示を反映する構成です。

文字列の反映後、表示内容が変わった場合にだけ演出状態へ通知します。演出側がタイトルの更新を遅延・間引きしたり、保持していた古い文字列を後から書き戻したりしません。演出を無効にした場合や描画処理が失敗した場合も、タイトルの更新は継続します。

非表示中は描画を止め、古い周期を順番に再生しません。その間もタイトルは更新し、再表示時には最新の文字列を表示します。終了時のフェードを採用する場合、その間の新しい変化も取りこぼさず、現在の背景から次の周期へ滑らかに移ります。

## 二つの演出と設定

BELは短い通知として優先します。グラデーションの位相を継続しながらBELの明暗変化を重ねますが、合成後の色差に上限を設けます。BELはタイトル変化の記憶や周期の終了判定を変更しません。通知後はその時点のグラデーションへ戻し、どちらも終了したら現在のテーマの背景だけを表示します。

設定候補は「BELの視覚通知」と「タイトル更新エフェクト」の二つです。各項目で無効を選べるようにし、採用方式と標準強度を初期値にします。比較用の方式すべてを製品の選択肢にするかは、段階1の見え方を見て決めます。グローバル設定の継承と接続ごとの変更を既存の設定モデルへ接続します。

初期推奨値はBEL A案、グラデーションA案です。GTKのアニメーション無効設定では、移動を止めて短い静的な背景変化だけにする案と、効果を無効にする案を比較します。これは表示設定の扱いとして決め、追加の確認ダイアログは導入しません。

## 描画方法

第一候補は、ヘッダーの背景にCairoで効果を描き、GTKのフレームクロックで位相を更新する方式です。[GtkWidget.add_tick_callback](https://docs.gtk.org/gtk3/method.Widget.add_tick_callback.html)と描画APIの公式文書・コメントを確認して採用します。フレーム数を時間の代わりに使わず、単調増加時刻から演出状態を求めます。

CSSアニメーションを使う案も比較しますが、GTK3でブラウザーと同じ`background-position`やグラデーション補間が使えるとは仮定しません。既存のタイトルバーに効果を差し込む最小構成を試し、背景、効果、文字・ボタンの順に描けることを確認します。ボタンの入力領域やドラッグ操作は維持します。

描画更新は対象ヘッダーだけに限定し、文字変更がないときにラベルやCSS全体を毎フレーム作り直しません。効果の終了・非表示・破棄でフレーム更新を停止します。コンパクト表示、テーマ切替、表示倍率、再アタッチで基準色やサイズを更新し、端末の行列数を変えないことを検証します。

## 段階1：既存ヘッダーで各案を比較する

BELとタイトル変更を任意に発生させるGTK試験用画面を、現在のヘッダー構成から作ります。各案を切り替え、単発・連続入力、暗色・明色・接続色、コンパクト表示を動画で比較します。

時刻を注入できる状態計算をテストし、開始、周期中の変化の記憶、境界での消費、継続、終了を先にRED・GREENで確認します。成果物は静止画だけでなく比較動画です。完了条件は、採用する見え方、初期値、二つの効果の重なり方が決まることです。

## 段階2：BEL通知を製品へ接続する

音の分岐の前で視覚通知を発生させ、標準音と独自音の両方で確認します。連続BEL、再生失敗、非アクティブ、最小化、ウインドウ破棄を試験します。

完了条件は、BELで背景が変わり所定の時間に戻ること、音の選択と再生動作を維持することです。動画のフレーム列から色変化と復帰を検証します。

## 段階3：タイトル変更の循環効果を接続する

最終表示文字列の変更を一か所で検出し、タイトルの反映と独立してグラデーションへ通知します。単発、周期の前半・後半・境界付近の変化、同一文字列、`A → B → A`、切断時表示、BELとの同時発生を試験します。

完了条件は、記憶がある周期末では切れ目なく継続し、記憶のない周期末で終了することです。動画で横方向への動きと境界の連続性を確認し、演出中の各タイトル更新が周期を待たずに反映されることもアサートします。

## 段階4：設定・表示・全体検証

設定の保存・継承・適用と、無効時に背景が元へ戻ることを確認します。複数ウインドウ間で効果が漏れないこと、テーマ変更、リサイズ、表示倍率、コンパクト表示を検証します。動画は決め打ちのsleepだけに頼らず、入力と描画の観測時刻を関連付けてアサートします。

撮影した画像・動画を目視確認し、通常のタイトルバー操作と端末入力の回帰試験、`make test`、利用者向け説明を完了させます。

## 最終完了条件

1. BELのフラッシュを複数案から選び、音の方式に関係なく動作する。
2. タイトル変更でグラデーションを開始し、周期中の変化を記憶する。周期末で記憶を消費してシームレスに継続し、変化のない周期末で終了する。
3. 二つの効果が重なっても文字とボタンを読め、テーマの背景へ正しく戻る。
4. タイトルは演出の位相・有効無効にかかわらず指示どおり更新する。非表示・破棄後に描画更新が残らず、ヘッダーの高さや端末の行列数に影響しない。
5. 動画による時間軸の検証、目視確認、全体テストが完了している。
