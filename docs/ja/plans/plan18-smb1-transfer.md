# plan18：SMBバージョン設定とlibdsmによるSMB v1

作成日：2026年11月2日

状態：段階1〜4を完了。WindowsのSMB2/3回帰試験に加え、2026年11月5日にWindows XPでのSMB1実機試験も成功しました。

## 目的と範囲

SMB設定にバージョン指定を追加し、SMB v1をlibdsmで利用できるようにします。SMB v2/v3は現在のlibsmb2を使う方針です。共有一覧、`/共有名/パス`、ファイル転送、再接続の操作を共通化します。

古いプロトコルを使う判断とそのリスクは、依頼どおり利用者の責任であり対象外です。本planでは対応する接続条件、ライブラリの能力、通信結果の正確さを扱います。調査基準と共通の実施条件は[plan15](plan15-transfer-jobs-and-tree-icons.md)に従います。

## バージョン設定

| 設定値の案 | 使用するバックエンド | 動作 |
| --- | --- | --- |
| `auto`・既定 | libsmb2 | 現在と同じSMB v2/v3の範囲でネゴシエーションする |
| `1` | libdsm | SMB v1を指定する |
| `2` | libsmb2 | 公開APIでSMB v2系に限定する |
| `3` | libsmb2 | 公開APIでSMB v3系に限定する |

`auto`の画面表示は「自動・SMB 2/3」とし、含む版を明確にします。SMB v1を選択した接続はv2/v3へ変更せず、認証や接続の失敗を別バージョンでやり直す契機にしません。v2/v3の限定方法は[採用中libsmb2の公開API](https://github.com/sahlberg/libsmb2/blob/727feaaa6d0f4fed1bae57745fbc2c5db9a30e64/include/smb2/libsmb2.h)で確認します。

設定の保存、グローバル値の継承、接続ごとの上書き、実行中の読み取り専用表示を既存の仕組みに合わせます。接続結果には実際に選択された版を表示できるようにし、指定と結果を検証します。

## libdsmの実行方法

[セッションAPI](https://github.com/videolabs/libdsm/blob/0f3edc6df6ab5950f2550d453035351440f71e31/include/bdsm/smb_session.h)は同期的に接続・認証を行います。中断APIはありますが、中断後のセッションは破棄だけが可能です。現在のlibsmb2のように、公開されたソケット駆動APIがあると仮定して実装しません。

第一候補は、libdsmの同期呼び出しを専用の補助プロセスで実行する構成です。アプリ側はCardioでIPCとプロセス終了を非同期に待ち、ワーカースレッドや待機ポーリングを追加しません。親がジョブと期限を持ち、子がlibdsmのセッションとファイルハンドルを所有します。

IPCでは要求ID、操作、引数、上限付きデータ、進捗、結果を送ります。資格情報の受け渡しもIPCを使う方針です。コマンドライン引数へは載せません。大きなファイルを一括でメモリーへ保持せず、受信側の処理量に合わせてチャンクを受け渡します。

同期呼び出し中の子に中止要求を処理させられるとは限りません。段階1では親から子を終了させて回収する方法を検証します。`smb_session_abort()`がスレッドから呼べることを、シグナルハンドラーから安全に呼べる根拠にはしません。中断後の再接続では新しいプロセスとセッションを作ります。

補助プロセスの終了でリモート変更が取り消されたとは判断しません。応答が得られなかった送信・名前変更は結果を不確実として記録し、一時ファイルの確認と後始末を共通転送の契約に従って行います。実行方式が要求を満たさない場合は、この段階の結果を受けて計画を改訂し、同期処理をGTKスレッドへ移して先へ進めません。

## 接続条件と能力の対応

| 項目 | 計画上の扱い |
| --- | --- |
| TCP 445とNetBIOSの139 | 公開APIのDirect TCP・NBTを検証し、設定した接続方法を使う。139では必要なNetBIOS名も確認する |
| 任意ポート | 調査した接続APIにはポート引数がない。公開APIで指定できるか段階1で確認し、未対応ならv1との組合せを入力エラーにする |
| IPv6 | 調査したAPIはIPv4値を受け取る。v1の到達性を未検証のままv2/v3と同じ対応範囲にしない |
| SSH proxy | 任意のソケットや中継先を渡せる公開経路を検証する。利用できなければv1では選べない組合せとして表示し、直接接続へ自動変更しない |
| 署名・暗号化の要求 | 採用版が満たす公開契約を確認する。満たせない明示設定は検証エラーにし、要求を無視して接続しない |
| ユーザー認証 | ドメイン・ユーザー名・パスワードを渡す。ゲストとして成立した接続を指定ユーザーの認証成功と誤認しない |
| 属性・リンク | 実装とサーバーで扱える能力だけを宣言する。対応しないPOSIX属性などを擬似的な成功にしない |

既定値はバージョンごとに定義し、SMB v1の標準設定で基本接続を試せる構成にします。ただし、利用者が明示または継承で要求した署名・暗号化の条件を、版の切替によって勝手に消しません。設定が成立しない理由を該当欄に表示します。

任意ポートやSSH proxyの制限は、採用版で確認する依存上の制約です。これらを補うためにlibdsmの内部関数や構造体、ソケットの差し替えに依存しません。基本対応の完了条件は直接接続とし、拡張接続は検証結果を残して対応範囲を確定します。

## ファイル名の文字コードとlibdsmの境界

SMB v1にはUnicodeと、旧来のコードページによるOEM文字列の区別があります。[MS-CIFSの文字列規定](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-cifs/d13dd8de-2504-4254-9f81-e351fc5baacd)に従い、SMB v1という版だけを根拠にCP932などの生バイト列を送る構成にはしません。

調査版の[公開共有API](https://github.com/videolabs/libdsm/blob/0f3edc6df6ab5950f2550d453035351440f71e31/include/bdsm/smb_share.h)と[公開属性API](https://github.com/videolabs/libdsm/blob/0f3edc6df6ab5950f2550d453035351440f71e31/include/bdsm/smb_stat.h)には、戻り値がローカルの文字コードであると記載されています。[変換処理](https://github.com/videolabs/libdsm/blob/0f3edc6df6ab5950f2550d453035351440f71e31/src/smb_utils.c)は環境によってロケールの符号化を参照し、`UCS-2LE`との間で変換します。[ファイル操作](https://github.com/videolabs/libdsm/blob/0f3edc6df6ab5950f2550d453035351440f71e31/src/smb_file.c)もこの変換を使用します。NFSのようにAPIへ渡した名前がそのまま通信上の名前になる前提は置けません。

第一候補は、plan18の補助プロセスで利用可能なUTF-8ロケールを選び、IPCとlibdsmの公開API境界をUTF-8へ揃える方法です。ライブラリが環境からロケールを再設定することも考慮し、親のGTKプロセスのロケールは変更しません。必要なロケールがない場合も無条件に成功扱いにせず、利用環境の条件として確認します。

OEM文字列だけを扱うサーバーへの対応は、公開APIで制御できるか段階1で検証します。調査した公開APIには、NFSの設定に相当するファイル名用コードページ指定は見当たりません。ロケールをCP932へ変えることだけでは、通信をOEM方式へ切り替えたことにはなりません。利用できない場合は対応範囲として示し、ライブラリの内部APIや外部ソースの修正で補いません。

`UCS-2LE`を使う版については、U+FFFFより大きい符号位置の文字を含む名前を、通常のUTF-16と同じ範囲で扱えると仮定しません。日本語名に加えて絵文字・異体字などを含む名前も試験し、変換失敗や列挙欠落を成功と誤表示しないことを確認します。既存SMB v2/v3はlibsmb2によるUTF-8・UTF-16変換を維持し、サーバー用の文字コード設定は追加しません。

## 共有とファイル操作

[共有API](https://github.com/videolabs/libdsm/blob/0f3edc6df6ab5950f2550d453035351440f71e31/include/bdsm/smb_share.h)で列挙し、既存と同じ`/`と`/共有名/パス`へ対応させます。列挙拒否でも既知の共有を開ける操作、空の共有、日本語名、アクセス拒否後に別共有へ移る操作を維持します。

SMB v1用の実装も`RemoteFileClient`を満たすようにし、画面へlibdsmの型を公開しません。共有ルートの変更禁止、遅延接続、plan15のアイコンとジョブは共通の契約を使います。共有間の名前変更は禁止します。

読み書きでは短い応答を処理し、0バイト書き込みが続く状態を無限に再試行しません。排他的作成、上書き、名前変更、一時ファイルの所有は実通信で確認し、API名だけから原子性を推定しない方針です。

## 段階1：SMB v1の実通信と中止を観測する

libdsmを固定し、承認された不具合修正だけをビルド用コピーへ適用します。サブモジュールは上流コミットのまま維持します。SMB v1だけを許すSamba環境で、補助プロセスを介した認証、共有一覧、1ファイルの読み書き、通信停止中のキャンセルを実行します。

親が非UTF-8ロケールの場合も補助プロセスの日本語名を正しく扱えること、変換不能な名前を誤操作しないこと、OEM専用サーバーの対応可否を確認します。公開APIから得られる名前の範囲と、制御できる文字列方式を記録します。

要求した版、UI側の応答性、子の回収、通信期限、再接続を確認します。接続条件の対応表を実測結果で埋めるところまでが成果物です。完了条件は、SMB v1の実通信と非同期の終了方法が成立し、対応範囲が決まることです。

## 段階2：既存SMBへバージョン設定を加える

設定の解析・継承・保存とUIを追加し、libsmb2の自動・v2・v3を動かします。v1は検証済みのドライバーと接続できる状態で有効にします。利用できない組合せを設定時に検出します。

完了条件は、選んだ版と実際の接続が一致し、認証失敗による別版への切替が起きないことです。設定だけが保存できて接続できない状態を完成扱いにしません。

## 段階3：SMB v1を転送画面へ統合する

共有のブラウズ、単一・再帰転送、フォルダー作成、名前変更、削除、属性取得を共通クライアントへ接続します。計画した能力を操作でき、共有ルートへの変更を拒否することを確認します。

完了条件は、GUIからSMB v1を選び、複数共有を閲覧して双方向転送を行え、ジョブの結果と受信内容が一致することです。

## 段階4：障害・回帰・全体検証

誤った資格情報、ゲスト接続、列挙拒否、アクセス拒否、日本語名、空の共有、大きなファイル、短い書き込み、補助プロセス異常終了を試験します。転送中・判断待ち・切断中に画面を閉じてもプロセスやファイルハンドルが残らないことを確認します。

libsmb2のSMB v2/v3、既存の署名・暗号化設定、SambaとWindowsの直接接続・SSH proxyを回帰検証します。Windows実機が必要な場合は既存agent-roverの手順で確保し、通信試験が終わったら解放します。画面と進捗動画、利用者向け文書、`make test`まで確認して完了します。

## 最終完了条件

1. SMB設定で自動・v1・v2・v3を指定でき、選択どおりのバックエンドで接続する。
2. libdsmで共有の列挙、既知共有への移動、双方向転送、基本的なファイル操作を実行できる。
3. UIを止めずに中止・切断・再接続でき、補助プロセスを確実に回収する。
4. 対応しない接続条件と文字列の範囲を明示し、指定した要求や経路を無視して接続しない。ロケールの変換と通信上のUnicode/OEMを混同しない。
5. SMB v2/v3の回帰試験と全体テストが通る。外部サブモジュールを変更せず、libdsmへの修正は承認された不具合修正パッチとして管理する。

## 段階1の結果と計画の変更

対象ディストリビューションの公式パッケージ検索ではlibdsmの供給を確認できませんでした。[Debianの検索](https://packages.debian.org/search?keywords=libdsm&searchon=names&suite=all&section=all)と[Ubuntuの検索](https://packages.ubuntu.com/search?keywords=libdsm&searchon=names&suite=all&section=all)を調べ、固定コミットのベンダー参照を採用しました。

上流版では、絵文字を含むディレクトリの一覧が途中で終わり、NT_STATUS=0となる不具合を再現しました。[変換処理](https://github.com/videolabs/libdsm/blob/0f3edc6df6ab5950f2550d453035351440f71e31/src/smb_utils.c)のUCS-2LEと、[一覧処理](https://github.com/videolabs/libdsm/blob/0f3edc6df6ab5950f2550d453035351440f71e31/src/smb_trans2.c)のエラー伝播が原因です。利用者から「libdsmの不具合修正を例外として許可する」と回答を得たため、UTF-16LEへの修正と部分一覧の破棄をパッチとして管理します。現行ツールチェーンのビルド警告もこのパッチで修正します。任意ポートやOEM対応などの機能追加には、この例外を適用しません。

| 確認項目 | 結果・対応範囲 |
| --- | --- |
| IPv4・TCP 445 | NT1限定のSambaで認証、一覧、読み書き、名前変更、削除が成功 |
| NetBIOS 139 | 公開APIのNBT指定とサーバー名ELDERTESTで同じ操作が成功。設定にNetBIOS名を追加する |
| 任意ポート・IPv6・SSH proxy | [接続API](https://github.com/videolabs/libdsm/blob/0f3edc6df6ab5950f2550d453035351440f71e31/include/bdsm/smb_session.h)に対応する指定がないため、v1では入力エラーにする |
| 署名・暗号化の要求 | 採用版の公開APIに要求を満たす指定がないため、v1では入力エラーにする |
| 日本語・補助平面の文字 | 修正後は日本語共有、絵文字ファイルと前後の通常ファイルを欠落なく列挙。転送内容も一致 |
| 親の非UTF-8ロケール | LC_ALL=Cの親から接続し、子だけC.UTF-8を使用。親のロケールを維持 |
| OEM専用サーバー | [送信処理](https://github.com/videolabs/libdsm/blob/0f3edc6df6ab5950f2550d453035351440f71e31/src/smb_message.c)はUnicodeを指定し、公開APIにOEM切替がないため対象外 |
| 通信中の中止・期限・切断・子異常終了 | 実通信の読み取り応答を中継で止めて確認。親はCardioで待機し、子を終了・回収して再接続可能 |
| 排他的作成と置換 | [ファイルAPI](https://github.com/videolabs/libdsm/blob/0f3edc6df6ab5950f2550d453035351440f71e31/include/bdsm/smb_file.h)に排他的ファイル作成指定がない。専用ディレクトリの新規作成で一時領域を確保する |

送信先を置換する際は、既存ファイルを一時領域へ退避してから新しいファイルを移動します。原子的な置換ではなく、置換中に送信先が存在しない期間があります。失敗時は退避ファイルの復元を試み、結果が不明なら一時領域のパスを後始末エラーとして残します。通信の中止を、サーバー側変更の取消しとは扱いません。

再現手順は`make -C elder-terms-file-transfer/tests/smb -f Makefile.smb1 test test-client`です。Sambaの445/139番ポートは使い捨てコンテナー内で開き、ホストのポート設定を変更しません。

## 段階2の結果

`version=auto|1|2|3`と`netbios_name`を追加しました。保存・再読込・グローバル値の継承を設定テストで確認しています。SMB1では組み込みの署名既定値だけを無効にし、明示値や継承値による署名要求はエラーとして残します。任意ポート、IPv6、SSH proxy、要求した暗号化も接続前に検証します。

Sambaとの実通信では、SMB2指定でSMB 2.10、SMB3指定と自動選択でSMB 3.1.1となりました。SMB2指定で暗号化必須の共有へ接続した場合は失敗し、SMB3へ切り替えません。SMB1も共通の接続窓口からNT1限定サーバーへ接続できます。接続結果の版はウィンドウのタイトルと転送ジョブへ反映します。

SMB1の実通信・障害試験を通常のMesonテストへ登録しました。ビルドには`libtasn1-6-dev`、`libtasn1-bin`、`doxygen`、`patch`を使い、配布物には補助プロセスとlibdsmの共有ライブラリ、対応ソース、ライセンスを含めます。

## 段階3の結果

初回の実機試験で、ファイル属性の問い合わせに`STATUS_INVALID_SMB`が返りました。原因は[採用版の`smb_fstat()`](https://github.com/videolabs/libdsm/blob/0f3edc6df6ab5950f2550d453035351440f71e31/src/smb_trans2.c)の要求形式です。要求の可変長部分のバイト数を表す`ByteCount`から、先頭の3バイトが抜けていました。また、データを送らない要求にも、データ位置として`DataOffset=96`を指定していました。この値は短いパスでは要求の範囲外になります。[MS-CIFSの要求形式](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-cifs/f7d148cd-e3d5-49ae-8b37-9633822bfeac)に従い、先頭部分を長さに含め、データ位置を0へ修正しました。

この2点は、既存の[libdsm修正パッチ](../../../patches/libdsm-correctness.patch)へ追加しました。サブモジュールの参照とソースは変更していません。XPと同じ条件で要求を拒否する中継を既存の障害試験に加え、修正前の失敗と修正後の成功を確認しました。属性の取得、日本語・絵文字名、存在しないファイル、短いパスを全体テストでも検証できます。
