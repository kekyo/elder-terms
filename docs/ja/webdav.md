# WebDAVの使用

## 接続を作成する

ランチャーの「一般」タブで接続タイプを「WebDAV」にし、WebDAVタブで接続先を設定します。HTTPSが既定です。HTTPを選択すると通信は暗号化されません。

例えば公開先が `https://files.example.com/dav/team/` の場合、接続の暗号化をHTTPS、サーバーアドレスを `files.example.com`、公開パスを `/dav/team/` にします。完成する接続URLを読取り専用の表示で確認できます。アドレス欄にURL全体やユーザー名・パスワードを入れないで下さい。

公開パスがファイルブラウザの `/` になります。その上へ移動することはできません。初期リモートディレクトリを `/Documents` にすると、この例では `/dav/team/Documents` から開始します。

## 設定項目

| 項目・INIキー | 既定値 | 指定方法 |
| --- | --- | --- |
| 接続の暗号化 `scheme` | `https` | `https` または `http`。 |
| アドレス `address` | 空 | ホスト名、IPv4、IPv6。接続時必須。 |
| ポート `port` | 443 / 80 | HTTPSは443、HTTPは80。1～65535。 |
| 公開パス `base_path` | `/` | 公開先URLの絶対パス。URLエスケープを使用できます。 |
| 認証方式 `authentication` | `auto` | `auto`（Basic/Digest）、`basic`、`digest`、`none`。 |
| ユーザー名 `username` | 空 | 認証オーバーレイで使用する初期値。 |
| ローカルディレクトリ `local_directory` | 空 | 共通の転送先設定、ダウンロード先へのフォールバックを使用。 |
| リモートディレクトリ `remote_directory` | `/` | 公開パス内の通常の表示パス。 |
| CA証明書 `ca_file` | システムCA | 独自指定ではPEMファイルの絶対パス。 |
| 証明書検証の失敗時 `certificate_error_action` | `reject` | 接続拒否、または `prompt` で確認。 |
| 接続タイムアウト `connect_timeout_seconds` | 30 | DNS・TCP・TLS確立の待機秒数。1～86400。 |
| 無通信タイムアウト `idle_timeout_seconds` | 60 | 通信が進まない待機秒数。1～86400。 |

各設定はグローバル設定から継承できます。ポートは接続固有値、明示されたグローバル値、方式別の既定値の順で決まります。方式を変更しても、明示したポートは変わりません。

CAの「継承」と「システムのCA証明書」は異なります。「システムのCA証明書」を明示すると、継承された独自CAの代わりにシステムCAを使います。HTTPではHTTPS設定欄が無効になりますが、入力済みの値は保持します。

接続中の接続条件は読取り専用です。保存した設定を変更した場合は、新しい接続ウィンドウを開いて反映します。認証・証明書確認の回答待ちや、ローカル入出力による意図的な転送停止は通信停止時間に含めません。

`base_path` の空白は `%20` のようにURLの表現で指定できます。`remote_directory` は `/日本語の資料` のように通常の名前を入力します。クエリー、フラグメント、`.`・`..` による移動、不正なエスケープは使用できません。

```ini
[general]
type=webdav
name=Team files

[webdav]
scheme=https
address=files.example.com
base_path=/dav/team/
authentication=auto
username=alice
remote_directory=/Documents
certificate_error_action=reject
```

## 認証

Basic/Digest認証では、接続時のオーバーレイでユーザー名とパスワードを入力します。パスワードは保存しません。アプリパスワードを要求するサーバーでも、同じパスワード欄を使用します。

`auto` はBasic/Digestの中で方式を選択します。認証なしでは認証情報を送信しません。Windows統合認証、NTLM、Kerberos、OAuth専用のログインには対応しません。

## ファイルを操作する

SFTP/FTP/FTPSと同じ2ペインのファイルブラウザを使用します。項目を選択して右クリックし、送信・受信、名前変更、削除を実行します。フォルダーは配下の項目も転送・削除します。「新しいフォルダー」は空の一覧でも使用できます。

サーバーがサイズを通知しないファイルは、サイズ欄を空にします。空のファイルとは区別し、転送中は取得できた情報に基づく進捗を表示します。サーバーが通知する更新日時は表示できますが、リモートのPOSIX権限、シンボリックリンク、日時の書き戻し、リモートハッシュ計算には対応しません。

アップロードは隣接する一時ファイルへ送り、サーバーの完了応答を受けてから最終名へ確定します。同名の転送先がある場合は上書き確認を表示します。通常の名前変更では同名の項目を置き換えません。WebDAVへの送信でファイルとフォルダーの種類が衝突した場合は、既存の内容を残して失敗を通知します。同名のフォルダー同士は配下を転送し、既存ファイルの置換で確認します。受信する通常ファイルと既存のローカルフォルダーが衝突する場合は置き換えず、フォルダーと子ファイルを保持します。

変更操作の最終応答前に接続が切れた場合、サーバーで処理が完了したか分からないことがあります。自動的に繰り返さず失敗を表示するため、一覧を更新してから再試行して下さい。一時ファイルが残った可能性がある場合や回収できなかった場合は、表示されたパスも確認して下さい。

## HTTPSの証明書確認

HTTPSはTLS 1.2以上を使用し、通常は証明書と接続先名を検証します。独自CAはPEMファイルとして指定できます。証明書検証に失敗した場合の既定動作は接続拒否です。

「オーバーレイで確認」を選ぶと、接続先、理由、証明書のSubject・Issuer・有効期間・SHA-256全体を表示します。「この接続で許可」は、そのウィンドウの表示された証明書と検証失敗だけに適用します。証明書や失敗条件が変われば再確認し、設定ファイルや信頼ストアには保存しません。許可は新しいウィンドウへ引き継ぎません。

中止が既定です。Esc、取消、ウィンドウを閉じる操作でも拒否します。許可前に認証情報やファイルを送ることはありません。許可後は一覧取得などの読取りを再開できますが、失敗したアップロード・名前変更・削除は自動再送しません。例外が有効な間はステータスバーに表示します。

証明書の許可によってTLSバージョンや暗号の条件を緩和することはありません。TLS交渉の失敗やCAファイルを読めない場合も、この確認では解決できません。

この確認方式は、libcurlとアプリケーションが同じOpenSSL版を使用する環境で利用できます。他のTLSバックエンドでは通常の証明書検証と拒否を使用して下さい。[libcurlのTLSコンテキストコールバック](https://curl.se/libcurl/c/CURLOPT_SSL_CTX_FUNCTION.html)がバックエンドごとのコンテキストを扱う仕様による制約です。

## 対応範囲と接続先の制限

標準的なWebDAVのファイル操作を対象とします。Nextcloudの独自分割アップロードや専用ログイン、IISのWindows統合認証、LOCK/UNLOCK、任意属性の更新、サーバー内COPY、同期・再開転送、クライアント証明書、プロキシ設定は対象外です。

読取り専用の公開先は、一覧・ダウンロードに使用できます。サーバーのアクセス権、ロック、容量、ファイルサイズやURLの制限によって操作を拒否された場合は、応答に基づいてエラーを表示します。

読取りのリダイレクトは、同じ接続先・公開パス内の範囲で追従します。別ホスト・別ポート・HTTPSからHTTPへの転送や、書込み操作の自動リダイレクトは行いません。ログイン用HTMLが表示されるURLではなく、WebDAVの公開先を指定して下さい。

転送内容を正しく保存するため、HTTP応答には非圧縮を指定します。この指定を無視して圧縮応答を返す公開先では、受信を失敗として扱います。HTTP圧縮を強制しないWebDAV公開先を使用して下さい。

実測結果は[WebDAV検証記録](webdav-validation.md)を参照して下さい。
