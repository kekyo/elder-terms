# plan28 boxrig 0.15.0追従計画

状態は実装中です。段階2の文字幅とセル順への追従まで完了しました。boxrig 0.15.0への依存更新と、端末の文字配置・画像表示の追従を扱います。各段階で実行可能なアプリを残し、対象試験を通してからコミットします。

## 対象と採用方針

調査対象はelder-termsの`a3c511e1`です。現在の`deps/boxrig`は0.14.0の`0abaeede569879a5fe1da3845e590a0f35e4d7bb`を参照しています。更新先は[0.15.0のリリース](https://github.com/kekyo/boxrig/releases/tag/0.15.0)に対応する`ee669104d58b64442f863906cc8a0a644c8ebb37`に固定します。

対象は現在のGTK3アプリと配布パッケージです。端末の描画方式はCairoとOpenGLを扱います。TUIとは、端末の行・列を指定して文字や枠を配置するアプリです。ライブラリーの更新に加え、boxrig付属端末`boxrig_term`と同じTUI向けの文字配置を採用します。

既存の曖昧幅文字設定、接続方式、再接続、リンク、選択、色補正を維持した状態で追従します。新しい表示方針はアプリの既定動作にします。設定UIの追加や対応OSの拡張は今回の対象外です。外部コードの修正は行わず、boxrigの参照更新とelder-terms側の変更で対応します。

## 差分と現在のコードへの影響

### 依存関係と配布SDK

SDKは、ヘッダー、リンク用ライブラリー、pkg-configの情報をまとめたものです。`scripts/prepare-boxrig.mts`と`scripts/prepare-package-tools.mts`は、どちらも`BOXRIG_VERSION=0.14.0`を指定しています。通常ビルド用のSDKを準備するのは前者で、配布ビルド用の生成済みツールとメタデータを準備するのは後者です。

`elder-terms/tests/package-build.test.ts`には、通常ビルドと生成済みツールの両経路で0.14.0を期待する試験があります。配置場所を変え、ターゲット側のnpmを利用不能にした状態でもSDKを構築して利用できることが検証対象です。更新後もこの性質を維持します。

公開ヘッダーの差分には、端末設定と表示設定の構造体へのメンバー追加があります。共有ライブラリーの名前が同じでも、旧ヘッダーで作った実行ファイルとの混在を認めません。`meson.build`で扱う5本のboxrig共有ライブラリー、背景効果用の静的ライブラリー、利用側の実行ファイルを同じソースから再ビルドします。追加APIと公開シンボルの根拠は[0.14.0から0.15.0の差分](https://github.com/kekyo/boxrig/compare/0.14.0...0.15.0)です。

バージョンの固定文字列は、依存ソースに対する`screw-up format -e '{version}' -f`の結果へ置き換えます。boxrigのソースディレクトリーを作業ディレクトリーとして実行する方針です。通常ビルドとホスト側の配布準備で同じ値を使い、配布準備で得た値を生成済みツールとともに保持します。ターゲット側ではその値を利用し、npmやGitによる再計算を必要としない構成にします。[screw-upのformatコマンド](https://github.com/kekyo/screw-up#format-command)に従い、タグ文字列を独自に解析しません。

### 文字幅と文字の並び順

絵文字表示を指定するVS16はU+FE0Fです。0.15.0では、VS16を追加しても元の文字の列幅を維持する`BOXRIG_EMOJI_VARIATION_WIDTH_PRESERVE`を選べます。ただし、ライブラリーの既定値は従来の`WIDE`です。現在の`create_terminal_runtime()`は曖昧幅文字の設定だけを指定しているため、依存更新だけでは新方針へ切り替わりません。[文字幅の公式説明](https://github.com/kekyo/boxrig/blob/0.15.0/docs/ja/fonts-and-layout.md)と[terminal.hのAPIコメント](https://github.com/kekyo/boxrig/blob/0.15.0/include/boxrig/terminal.h)を根拠に、端末の作成時にPRESERVEを指定します。

表示には`BOXRIG_TEXT_DIRECTION_LOGICAL`を採用します。アラビア文字などの字形を整える処理を使いながら、端末が保持するセル順に配置する設定です。従来の`AUTO`は双方向文字を並べ替えるため、混在行の見た目が変わります。`FORCE_LTR`でも行内の並べ替えは残るので、代用にはしません。[text_layout.h](https://github.com/kekyo/boxrig/blob/0.15.0/include/boxrig/ui/text_layout.h)と[GTK3の使用例](https://github.com/kekyo/boxrig/blob/0.15.0/examples/boxrig_term/gtk3/application.c)に従い、`boxrig_gtk3_terminal_widget_set_text_direction()`で指定します。

設定箇所は`elder-terms-terminal/src/terminal-runtime.cpp`です。文字幅は`create_terminal_runtime()`で決め、表示順は`attach_widget()`で設定します。後者は描画失敗後のウィジェット再生成にも使われるため、初回表示と復旧後で同じ方針を保てます。失敗時は既存のUIエラー処理へ渡し、設定に失敗したまま表示を続けません。

### ブロック文字とKitty画像

0.15.0では、塗りつぶしブロック文字をセルに沿った矩形として描く動作が既定になります。隣り合うブロックの隙間を抑える変更です。網掛け、罫線、結合文字付きのブロック、IME入力中の文字はフォントで描きます。保存する文字やコピー結果は変わりません。elder-termsではこの既定値を採用します。[描画方式の公式説明](https://github.com/kekyo/boxrig/blob/0.15.0/docs/ja/renderers.md)と[view.hのAPIコメント](https://github.com/kekyo/boxrig/blob/0.15.0/include/boxrig/ui/view.h)が対象範囲の根拠です。

Kitty画像プロトコルでは、配置ID付きの画像保存`a=t,p=...`の受け付けと、削除`a=d`で応答を返さない動作が修正されています。OpenGLでは、画像転送用バッファより大きい画像の分割転送と、描画済み資源の回収も修正されました。これらは依存更新で取り込めます。現在の`terminal-graphics.test.ts`は、2×2画素の分割画像を表示する試験です。大きい画像や繰り返し更新の確認を追加します。根拠は[画像プロトコルの差分](https://github.com/kekyo/boxrig/compare/0.14.0...0.15.0)と[上流の画像転送の検証記録](https://github.com/kekyo/boxrig/blob/0.15.0/docs/ja/plans/step19-notcurses-evaluation.md)です。

### 描画性能と既知の制約

0.15.0には、画像入力のまとめ処理、非圧縮RGBA画像の復号、Cairoの文字配置・色・字形の再利用に関する改善があります。elder-termsでの検証対象は、前景色のアニメーション、選択、リンクの強調、反転、半透明背景の更新です。上流の改善率をelder-termsの性能として扱わず、現在の遅延試験と同条件の比較で判断します。[上流の性能検証記録](https://github.com/kekyo/boxrig/blob/0.15.0/docs/ja/plans/step20-notcurses-rendering-performance.md)には、局所的な改善と実デモ全体の結果が分けて記録されています。

notcurses 3.0.7のmojibakeデモには、送信側の文字分割・幅計算による背景欠けが残っています。上流では入力と画素を照合し、送信された余分な空白による上書きを確認しています。この既知事象を、新しい描画不具合と混同しません。端末側で空白を無視する補正も加えません。出自は[0.15.0に含まれる再確認記録](https://github.com/kekyo/boxrig/blob/0.15.0/docs/ja/plans/step19-notcurses-evaluation.md#mojibakeの背景欠損の再確認)です。新たな欠けを観測した場合は入力まで調べ、同じ原因かを確認します。

## 段階1 リリース更新と動作するSDK

最初に0.14.0の実行ファイルと検証条件を記録し、比較できる状態を残します。旧版との比較には独立したソース・ビルド環境を使い、ライブラリーとヘッダーを混在させません。既存の`boxrig_source`オプションは、比較用のソースを指定する際に利用できます。

変更前に、SDKの報告バージョンを0.15.0とする試験と、配置ID付き画像の保存・表示、削除時の応答の試験を追加してREDを確認します。画像保存だけでは表示されず、表示要求で指定した位置へ描画されることが期待する動作です。削除の無応答は固定時間の待機で判定せず、後続の問い合わせへの応答までを区切りとして検査します。

その後、`deps/boxrig`をリリースのコミットへ更新します。2本の準備スクリプトを直し、取得したバージョンを配布用の生成済み情報にも渡します。SDKの準備と同梱処理は`meson.build`を含めて確認します。新規ビルドと既存ビルドディレクトリーからの更新をそれぞれ検証し、古い生成物が残る問題を検出します。

`make build`でアプリとドライバーを作成します。`package-build.test.ts`のSDK試験、`shared-library.test.ts`、`heap-allocator.test.ts`、画像試験を実行し、ローカル端末の起動・文字入力も確認します。生成済みツールの移動後に、ターゲット側のnpmを使わず公開APIを利用できることも確認対象です。

この段階は、5本の共有ライブラリーのpkg-config情報が0.15.0を報告し、同じ版のヘッダーとライブラリーでアプリが起動すれば完了です。追加した画像試験がGREENとなり、通常・配布準備の両経路が成功した状態で`chore: adopt boxrig 0.15.0`としてコミットします。

## 段階2 TUI向けの文字幅とセル順

0.15.0の既定値を使う段階1の実装に対し、アプリで必要な文字幅と並び順の試験を追加します。`tests/cpp/terminal-cell-width-test.cpp`を中心とした検査対象は、VS16を伴う文字の後続セルとカーソル位置です。GUIでは左右方向の文字が混在する行を用い、描画位置、クリック位置、ドラッグ選択、コピー内容、リンク位置を確認します。RED確認後、端末作成時とウィジェット作成時の設定を変更してGREENとなることを確かめます。

この段階は、PRESERVEとLOGICALを有効にしたアプリを起動でき、CairoとOpenGLで文字幅・表示・操作の試験がGREENになれば完了です。復旧後の表示、既存の曖昧幅設定、IMEの挙動まで確認し、`feat: align terminal layout with boxrig TUI policies`としてコミットします。

## 段階3 描画更新と画像処理の回帰確認

この段階で拡張するのは、既存の`terminal-graphics.test.ts`と`terminal-truecolor.test.ts`です。次の動作をアプリ経由で確認します。新しい試験で上流修正の効果を検証する場合は、段階1で残した旧版に同じ外部入力を与えてREDを確認します。比較には旧版の実行ファイルを使い、新APIへ移行した製品と旧ライブラリーの混在を避ける方針です。

| 対象 | 確認する動作 |
| --- | --- |
| ブロック文字 | 半ブロックや四分割ブロックの境界に隙間がなく、文字列のコピー結果を保つ |
| 描画範囲 | 網掛け、罫線、結合文字、通常文字を欠落させずに描く |
| 色の更新 | 同じ文字の前景色変更、反転、選択、リンク強調、カーソル点滅が画面へ反映される |
| 画像の転送 | RGBAで4 MiBを超える画像を表示でき、分割入力でも画素が一致する |
| 画像の寿命 | 表示・置換・削除を繰り返しても、残像や画像欠落がなく入力を続けられる |
| 復旧と終了 | 再描画、再接続、ウィンドウ終了で画像の残留や異常終了がない |

画像の容量はOpenGLの転送用バッファを超え、画像全体の許容容量には収まる値を選びます。既存のパディング付き分割画像と空の終端チャンクの試験も残します。通常の80列24行と拡大した画面が検証対象です。拡大時には実際の行列数・セル寸法も記録します。

描画の時間変化は動画から検証します。前景色と画像の状態を順に変更し、期待する画素を観測してから次の入力を送ります。画像の最終削除まで確認し、動画の代表フレームを目視でも確認します。画像比較のマスターを変える必要があれば、差が新しい仕様によるものかを先に確認します。

`tests/cpp/terminal-render-work-test.cpp`と既存の`test:latency`を実行し、不要な再描画、リンクの点滅、入力の取りこぼしを確認します。比較計測ではフォント、画面寸法、描画方式、入力をそろえ、他のビルドや試験を止めます。処理時間とメモリー使用量は、繰り返し測定のばらつきとともに記録します。再現する性能悪化があれば原因を調べ、タイムアウト延長だけで合格にはしません。

notcursesが利用できる環境では、現在のelder-termsでデモを補助実行します。録画による確認対象は、通常・拡大サイズでの進行、画像表示、終了後のシェル復帰です。既知のmojibakeの問題や配布データ省略によるSKIPPEDは、成功した項目と分けて記録します。ソフトウェアOpenGLと実GPUの結果も区別します。

この段階は、両描画方式で画素・動画・操作の試験に成功し、既存の遅延試験が通れば完了です。新たな表示異常や再現する性能悪化を残さず、`chore: verify boxrig 0.15 rendering regressions`としてコミットします。アプリ側の修正が必要になった場合は、再現試験から根本原因を直し、独立した`fix:`コミットにします。

## 段階4 配布と文書と全体試験

`elder-terms/tests/package-build.test.ts`では、生成済みツールから作るSDKの公開APIと、新しい共有ライブラリーの読み込みが確認対象です。debへ同梱したライブラリー、依存関係、ライセンスを確認し、クリーンなコンテナへインストールして起動します。検証順は、ホストと同じアーキテクチャー、既存のDebian trixie i386試験による32ビット構成、残りの対応構成です。対応済みの9構成を`build_package_all.sh`の生成・インストール検証で確認し、未実行の構成を合格に含めません。

この段階は、配布パッケージの検証、日本語・英語の文書更新、全体試験が完了すれば終了です。文書を`doc: document boxrig 0.15 terminal behavior`としてコミットし、最後に完了条件と実測結果を照合します。

## 段階2の結果
